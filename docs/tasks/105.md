# #105 乱数の種が実ゲームで配線されていない

## 症状

`Simulation.reset_match()` は #88a で第5引数 `seed` を受け取るようになったが、
**実ゲームの呼び出し3箇所すべてが省略している**。

    src/display/game_view.gd:103   reset_match(state, cfg, 0, r)
    src/display/main.gd:22         reset_match(state, cfg, 0)
    src/net/sim_root.gd:26         reset_match(state, cfg, 0)

既定値は `seed: int = 0` なので、**実ゲームは必ず `rng = aitick = 0` で始まる**。
最初の1コマは `advance_frame(0, 0) = 0x4017` で固定され、以降も同じ系列をたどる。

## 原作はどうしているか

起動時に DOS の時刻取得を1回だけ呼び、その値をそのまま種にする
（`0x9C00`: `mov ah,0x2c` / `int 0x21` → `RND = CX = 時<<8|分`、続けて `aitick = RND`）。
**試合・セット・ラリーのどこでも再初期化しない。**
詳細は `docs/tasks/88.md` の (d)。

つまり原作には「起動ごとに系列を散らす」機構がある。本作には入口だけあって
配線が無い。**原作にある機構を使っていない**ので、原作準拠の既定に反する。

## 影響の範囲

過大評価しないこと。人間が入力する限り、打球のたびに `aitick += rng` が走って
系列は散る。原作の (d) も「人間の打球タイミングが系列を散らす」と書いている。

固定されるのは次。

- **試合開始からサーブ打球までの判断**。この間 `aitick` は 0 のままなので、
  `aitick % 256 == 0` となり、しきい値が正である限り許可抽選が全て通る
  （#88b-2 で許可抽選を生の `aitick` へ移した後）
- **CPU 同士の完全自動試合**。人間の入力が無いので散らす要素が無く、
  同じ組み合わせなら毎回まったく同じ展開になる

## 範囲（Claude Code と Codex が3往復して合意。2026-07-28）

**#105 は「プロセス起動時に取得した時計種を最初の実ゲーム sim へ配線し、
ネット対戦で合意する」だけを扱う。プロセス内の後続試合へ生きた
`rng` / `aitick` を継承する契約は扱わない**（→ `docs/tasks/106.md`）。

したがって **「原作どおりプロセス終了まで再初期化しない、を達成した」とは
書いてはならない。** そこは #106 で未達のまま残る。

## 決めたこと

1. **換算は純関数。** `SimRng.seed_from_clock(hour, minute) = (hour << 8) | minute`。
   原作の式そのまま。OS 時刻の読み取りは `src/sim/` の外に置く。
2. **範囲外はマスクせず契約違反として停止。** `0 <= hour < 24` / `0 <= minute < 60`。
   種 0 への黙ったフォールバックはしない。
3. **所有者は `root.gd`。** static キャッシュは使わない。`root.gd` は
   **不変の `boot_seed` だけ**を持ち、生きた `rng`/`aitick` の所有者とは呼ばない。
   `_ready()` は「インスタンスごとに1回」であって「プロセスで1回」ではない
   （`root.gd:50` が GameView を作り直し、`root.gd:129` がデバッグ sim を別途作る）。
4. **デバッグビューは対象外。** `main.gd` は開発計器で原作に対応物が無い。
   **固定種 0 を維持する**（F1 を押した時刻でデバッグ結果が変わらないように）。
5. **ネット対戦の初期化は (う) 方式。** 新品の `SimState` へ `reset_match` してから
   `load_int_array` で既存 state へ転写する。`state` オブジェクトの参照が保たれるので
   GameView が追従し、`reset_match` の上書き漏れに依存しない
   （`to_int_array` は最上位44フィールドすべてを運ぶ）。
   **転写後に再設定が必須なのは `human_team_mask` と、直列化外の `_team_inputs`。**
   `p.cpu` のような app 所有の設定は、正式な出所から設定する。
   **仮状態を丸ごと保存して無差別に戻すことは禁止**（仮初期化を情報源にしてしまう）。
6. **ACK は種と `state_hash` の照合まで。** ホストが種を送り、クライアントが適用して
   `seed + state_hash` を返し、ホストが送信者 ID・種・ハッシュを照合し、
   全件一致したときだけ `SyncManager.start()`。
   異なる種・開始後の種・ハッシュ不一致は停止。
7. **ロールバック**。種そのものではなく `rng` / `aitick` の現在値が復元されれば
   よい。これは #88a で `SimState` へ入っているので**すでに満たされている**。
8. **リプレイは拡張点の名前だけ置く。** `boot_seed` はセッションのメタデータで、
   `SimState` にも state hash にも入れない。**「種だけで途中の再戦を再生できる」とは
   書かない**（途中から再生するには試合開始時の2ワードが要る。→ #106）。
9. **テスト**。既存テストは `seed` 0 を明示済み（#88b-3 第1段階）なので影響なし。
   `reset_match` の seed 伝播は `test_stateful_rng_part_a.gd:65` が既知ベクタで
   すでに検査しているので重複させない。

## 動くはずの固定値: ゼロ

テストは seed 0 を明示済みなので、ゴールデンは1つも動かない。
**1つでも動いたら「テストが実ゲームの経路に依存していた」という発見**になる。

## 先取りしてはいけないこと（#106 へ移管）

- 再戦でも同じ boot seed から再開することをテストで固定する
- `boot_seed` を `match_seed` や「乱数所有者」と命名する
- seed を `SimState` / state hash / ロールバック状態へ入れる
- seed だけで任意の試合を再生できるとリプレイ仕様へ固定する
- `reset_match()` へ2ワード継承や preserve モードを先回りで足す

## 着手の前提

#88 の乱数移行が終わってから（#88b-3 まで完了済み `19b772c`）。
移行中に種の入口を動かすと、挙動が変わった原因を切り分けられなくなる。
