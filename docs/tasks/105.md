# #105 乱数の種が実ゲームで配線されていない

## 症状

`Simulation.reset_match()` は #88a で第5引数 `seed` を受け取るようになったが、
**実ゲームの呼び出し3箇所すべてが省略している**。

    src/display/game_view.gd:103   reset_match(state, cfg, 0, r)
    src/display/main.gd:22         reset_match(state, cfg, 0)
    src/net/sim_root.gd:26         reset_match(state, cfg, 0)

既定値は `seed: int = 0` なので、**実ゲームは必ず `rng = aitick = 0` で始まる**。
最初の1コマは `advance_frame(0, 0) = 0x4017` で固定され、以降も同じ系列をたどる。

## 原作はどうしているか

起動時に DOS の時刻取得を1回だけ呼び、その値をそのまま種にする
（`0x9C00`: `mov ah,0x2c` / `int 0x21` → `RND = CX = 時<<8|分`、続けて `aitick = RND`）。
**試合・セット・ラリーのどこでも再初期化しない。**
詳細は `docs/tasks/88.md` の (d)。

つまり原作には「起動ごとに系列を散らす」機構がある。本作には入口だけあって
配線が無い。**原作にある機構を使っていない**ので、原作準拠の既定に反する。

## 影響の範囲

過大評価しないこと。人間が入力する限り、打球のたびに `aitick += rng` が走って
系列は散る。原作の (d) も「人間の打球タイミングが系列を散らす」と書いている。

固定されるのは次。

- **試合開始からサーブ打球までの判断**。この間 `aitick` は 0 のままなので、
  `aitick % 256 == 0` となり、しきい値が正である限り許可抽選が全て通る
  （#88b-2 で許可抽選を生の `aitick` へ移した後）
- **CPU 同士の完全自動試合**。人間の入力が無いので散らす要素が無く、
  同じ組み合わせなら毎回まったく同じ展開になる

## 決めること

**方針は原作準拠で決まる**（起動時に1回だけ種を作り、以降は再初期化しない）が、
本作にしか無い事情があるので、そこは設計が要る。

1. **ネット対戦の決定論**。両者が同じ種を持たなければ即座に同期がずれる。
   起動時刻をそのまま使うことはできない。ホスト側が種を決めて配り、
   両者が同じ値で `reset_match` を呼ぶ形になる。
2. **ロールバック**。種そのものではなく `rng` / `aitick` の現在値が復元されれば
   よい。これは #88a で `SimState` へ入っているので**すでに満たされている**。
3. **リプレイ**。種を記録すれば同じ試合を再生できる。どこに保存するか。
4. **テスト**。既存テストは `seed` 省略＝0 に依存している。実ゲームだけ種を
   入れるのか、テストも明示するのかを決める。**テストが `aitick = 0` を
   前提にしている限り、原作では起こらない状態を検査し続けることになる。**

## 着手の前提

#88 の乱数移行が終わってから。移行中に種の入口を動かすと、挙動が変わった
原因を切り分けられなくなる。
