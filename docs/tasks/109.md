# #109 表示層のパース検査が空振りしている

## 症状

**`test_display_parse.gd` は、表示層スクリプトがパースエラーでも赤くならない。**

```gdscript
var res := load("res://src/display/" + f)
check(res != null, "パース成功: " + f)
```

`load()` はスクリプトのパースに失敗しても**非 null の `GDScript` を返す**。
よって `res != null` は常に真で、この検査は何も検出していない。

## 実測（2026-07-28、#106 の変異検査中に発見）

`root.gd` に確実なコンパイルエラー（`var broken: NotARealType = 1`）を入れて全件実行。

```
ERROR: Failed to load script "res://src/display/root.gd" with error "Parse error".
PASS  test_display_parse.gd.test_display_scripts_parse
```

**`root.gd` 固有ではない。** `game_view.gd` に同じものを入れても同じだった。

```
SCRIPT ERROR: Parse Error: Could not find type "NotARealType" in the current scope.
ERROR: Failed to load script "res://src/display/game_view.gd" with error "Parse error".
PASS  test_display_parse.gd.test_display_scripts_parse
```

**この検査は最初から空振りだった可能性が高い。** 冒頭コメントは
「`game_view.gd` の `var on :=` を検出するために作った」と書いているが、
少なくともハードなパースエラーは1件も捕まえない。

## なぜ危ないか

このテストの存在理由そのものが冒頭コメントに書かれている。

> 表示層のパースエラー(型推論不能など)がテスト全緑のままゲームだけ壊す事故が
> 実際に起きた

**その事故を防ぐために作られた検査が、その事故を防いでいない。**
しかも「表示層は守られている」という誤った安心を与えている。#108 と同じ構造で、
本プロジェクトの中心テーマ（緑は健全さの証拠ではない）そのもの。

## 実際に守っていたもの

皮肉なことに、`root.gd` と `game_view.gd` のコンパイルエラーを実際に赤くしたのは
**#106 で追加した `test_boot_seed.gd` の結合テスト**だった
（`test_local_rematch_inherits_two_words_and_clears_root_handoff` と
`test_game_view_consumes_rng_words_and_external_state_is_untouched`）。

#106 の設計書 TEST-106-007 は「結合テストだけへ依存してはならない」と決めたが、
**現状はその結合テストだけが効いている。** 依存関係が逆になっている。

## #106 凍結設計書の正誤

凍結版（759行 / SHA-256 `ef9a473c...`）は履歴資料として維持する。未達は次の4件に限る。

- `CONTRACT-106-012`：除外撤去というコード形は達成、保護効果は未達
- `TEST-106-005` 4行目：指定変異が未検証
- `TEST-106-007`：主パース保護が成立せず未達
- `VERIFY-106-009`：静的形状は達成、動的検証は未達

4件とも原因は #109 と同じく、`load()` がパース失敗でも非 null を返すことにある。
解消先は #109 へ集約する。

**(12) は閉じる。** Codex の `git diff` は読み取りなので Claude Code 側の Godot 測定へ影響しない。
汚染されたのは Codex 側のスナップショットであり、「461本中2本だけ赤」の測定は有効。再測定は不要。

## 修正契約

`test_display_parse.gd` の判定に
`res is GDScript and res.can_instantiate()` を採用する。
`root.gd` へ型推論不能式を入れた実測は次のとおり。

| 判定式 | 健全時 | パース失敗時 |
|---|---:|---:|
| `res != null` | `true` | `true` |
| `res is GDScript` | `true` | `true` |
| `res.can_instantiate()` | `true` | `false` |
| `res.reload()` | `0` | `43` |

**合格条件:** `root.gd` へ型推論不能式を入れると
`test_display_scripts_parse` 自身が FAIL し、`test_display_parse.gd` だけを含む実行で
`1 tests, 1 failed` と終了コード非0になる。

**停止条件:** 変異を入れても対象テストが PASS のままなら、止めて相談する。

## 決定

1. **有効な判定方法。**
   `res is GDScript and res.can_instantiate()` を使い、テスト内で守る。
2. **`src/net` の扱い。**
   #109 の契約達成に必須ではないため別件へ回す。
   `scripts/run_net_test.ps1` が実際にパースエラーを検出できるかは未確認のままとする。

## あわせて検討したい小物

`run_tests.ps1` へ **CRLF 検査**を足す。`.gitattributes` は `*.gd` 等を LF に
固定しており `core.safecrlf=true` がコミットを止めるので**履歴は汚れない**が、
気づくのが最後のコミット時になる。テスト時に落とせば痛みが消える。
2026-07-28、Codex の実装で `tests/unit/test_sync.gd` が全行 CRLF 化した実例あり。

## 着手の前提

急がないが放置しない。#108 と同じ「二段目が効いているので実害は限定的」な形。
ただし #108 は二段目が実際に止めたのに対し、**こちらは二段目も止めていない**
（`run_tests.ps1` は `Failed to load script` を見ていない）。
`root.gd` のケースで exit 255 になったのは Godot 側の異常終了が偶然拾われただけで、
`game_view.gd` のケースは結合テストが落ちたから赤くなったにすぎない。
**検査として設計されたものは、どちらの場合も緑だった。**
