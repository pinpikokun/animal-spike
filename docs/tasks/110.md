# #110 `src/net` のパース検査能力を確認する

## 背景

`test_display_parse.gd` は `src/net` を対象にしない。ネット層は `SyncManager` の
autoload を前提とするため、`scripts/run_net_test.ps1` がパース検証を担う建て付けである。
ただし、このスクリプトがパースエラーを実際に検出できるかは未確認で、#109 と同じく
壊れても緑になる可能性が残る。

## 現物

通常モードはホストと参加側を起動した直後に終了コード0を返し、ログを検査しない。
`-VerifyBootSeed` モードは四つの標準出力・標準エラーログを監視し、同期開始行と
`SCRIPT ERROR` を検査するが、`Failed to load script` は直接検査しない。

`src/net` の四つの `.gd` は、`net_match.tscn` から読み込まれる `net_match.gd` と、
そこから `preload` される三ファイルである。構造上の到達だけを検出証拠にはしない。

## 決着方法

1. 健全な状態で `run_net_test.ps1 -VerifyBootSeed` が終了コード0になることを確認する。
2. `src/net` の各 `.gd` へ一つずつ、`SCRIPT ERROR:` を出す型推論エラーと、
   `Failed to load script` だけを出す別種のパースエラーを入れる。
3. 各変異で終了コード、失敗理由、四ログを記録し、変異ごとに元へ戻す。
4. 全変異が終了コード非0なら検出成立、終了コード0が一件でもあれば検査を是正する。

通常モードの起動成功は合格証拠に使わない。急がないが放置しない。
