# 2. #100 ネットを越えて相手コートへ返す球を作り直す（大部分完了）

**状態（2026-07-29）:** 固定速度返球、網羅保証、自陣トス248/136px、
地上・空中の3打目強制は実装済み。残る `serve_line_px` 14pxは、スパイク固定速度化後も
標準ジャンプCのアタックサーブがネットを越えず、承認設計の前提が実測で否定された。
現行値31pxへ復元済み。打点・速度・照準を変えず、方針をユーザーが再決定するまで保留する。

**中身**: サーブ（トスサーブ）と3打目の返球を、原作と同じ「速度を直接決める」方式にする。
今は落下点を決めて速度を逆算しており、**相手コートに入る保証が無い。**
落ちる場所は立ち位置・打点の高さ・入射・トス上手下手の4つで変える（乱数ではない）。
3打目の強制（原作 `0x56CF`）と、自陣トスの落下点を原作へ戻すのも同時にやる。

**設計書**: `docs/superpowers/specs/2026-07-26-return-over-net-design.md`。**ユーザー承認済み。**

**根拠**: 実測。自陣トスの落下点を原作の値へ変えたところ、
同じ設定が敵陣側も動かしていたため **CPUのサーブがネットに当たって越えなくなった**
（`test_cpu_serve_crosses_net` が落ちた）。今の数値でたまたま成立しているだけと判明した。

**なぜP0か**: 今の作りは数値を1つ動かすと壊れる。しかも #66 第4段はCPUの打ち方を調整する作業で、
返球の作りが変わる前提で調整すると二度手間になる。**#66 第4段より先にやるとユーザーが決定。**

## 2026-07-29 14px再実測

実ネット通過を `serve_flight` の1→0とネット中央の通過高さで測る検査を追加した
（`c70c380`）。31pxでは通常サーブと、CARBY（ジャンプB）の左右・全得点11x11・
全配置3種のアタックサーブが全件通った。256pxへの一時変異では新検査が赤になり、
未通過を検出できることも確認した。0pxはサーブ前clampで14pxへ補正されるため、
有効な変異にならなかった。

14pxへ変更すると、CARBYの728件は通る一方、`STANDARD_CHAR=99`（ジャンプC）の
最強CPUアタックサーブが左右とも未通過になった。正規入口は488件中5件失敗で、
直接失敗は左右サーブ2件、連鎖失敗はCPU役割、試合KPI、同期ゴールデンだった。
同期ハッシュは旧 `-7934760329014079569` に対し `-2200592025615985932` となったが、
他4件が赤のため張り替えていない。

同一条件の実測:

- 31px / ジャンプC: 打点y=159px、vx=11px/tick、vy=1px/tick、24tick後に通過
- 14px / ジャンプC: 打点・初速は同一だが、57tick後に自陣床へ落ちて未通過
- 14px / ジャンプB: 打点y=147px、vx=11px/tick、vy=1px/tick、25tick後に通過

固定速度化は成立している。差はジャンプBとCの打点高さであり、14pxで増えた17pxの距離を
ジャンプCが越えられない。承認設計6.3.1の前提が不成立なので、設計が禁じる打点上昇や
速度・照準の変更では修復しない。

検査はその後、実在するジャンプA/B/C/Eへ拡張した（`2ab1bc3`）。Bは726件全走査、
A/C/Eは31pxで全得点を測った最悪得点を左右・3配置で固定した。Eは31pxでも
ネット上端まで3304固定小数単位（約0.05px）の余裕しかない。全121得点の照準写像も
二重指紋で固定し、写像変更時は最悪得点の再測定が必要になる。拡張後の正規入口は
490 tests、0 failed、`SCRIPT ERROR` 0件。

## ユーザー再決定待ち

- 31pxを正式値として確定し、14px決定を撤回する（Codex / Claude Code 推奨）
- 打点上昇を解禁する
- サーブ線をジャンプランクまたはサーブ種別で分ける（原作根拠は未確認）
- clamp下限の14pxは維持し、別のサーブ要素でネット通過余裕を作る

後ろ3案は独自仕様または決着済み判断の変更になる。ユーザー決定なしで実装しない。
