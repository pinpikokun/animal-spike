## 実測で原因が確定した（2026-07-27、Claude Code が Godot ヘッドレスで計測）

テストと同じ条件（得点11×11 × 配置3 × サーブ側2 = **726通り**）を実走させ、
サーブの打撃が起きる瞬間の状態をそのまま読み出した。

**一次原因: 出目が726通りすべてで「4＝トス」だった。候補評価に一度も到達していない**
（落下点の計算回数0）。①②③が無効だから安全弁でトスに落ちた、のではない。

出目のキーは `s.last_hit_tick`（設計書 4.3）。**726通りすべてで `last_hit_tick=61`。**
`serve_delay_ticks=60` で、`s.tick` はラリーをまたいでも試合開始からリセットされないため、
**どの試合でも「開始直後の最初のサーブ」のトス打撃は必ず tick 61 に起きる。**
そして `_noise(SALT_AIR_SHOT, 61, 0) % 4 == 3`。

ハッシュ自体は正常（`last_hit_tick` 0〜1999 で 491/494/540/475 とほぼ均等）。
**キーが固定であることだけが原因。** 2球目以降は tick が進むので出目は散る。
つまりこれはテストの都合ではなく、**全試合の1本目のサーブが必ずトスになる**という
遊びの側の欠陥でもある。

**二次原因: 出目を直しても手前へは落ちない。** 3つの打ち方の内訳（726通り）:

| 打ち方 | 実際に有効 | 試し打ちで有効 |
|---|---|---|
| ①手前 | **0/726** | 0/726 |
| ②中央 | 252/726 (35%) | **0/726** |
| ③奥 | **726/726** | 420/726 (58%) |

- **①手前**: 実も試も常に無効。「本当に届かない」で判定は正しい。従来の記述どおり。
- **②中央**: **実際に越える252件が、試し打ちでは1件も有効にならない完全な偽陰性。**
  設計書 4.4 / 4.9 が実速度に (5/6, 14/12) を掛けているため。従来の記述どおり。
- **③奥**: 「実際も見積もりも有効」は**半分だけ正しかった**。実際は常に有効だが、
  **試し打ちでは306/726がネット越え判定で落ちている**（落下点は相手コート内なのに
  `_clears_net` が false）。倍率 (6/7, 1) の横速度減が効いている。

**だから②を救わないとテストは緑にならない。** 実測での落下点は
③奥＝458〜479、②中央＝309〜318。テストが要求する「相手コート幅の手前半分」は
288〜432 なので、**手前半分に落ちるのは②だけ**。③とトスはどちらも奥にしか落ちない。

**要修正は2箇所とも設計書側**: 4.3 の出目のキーと、4.4 / 4.9 の試し打ち倍率。

原作のサーブは専用の打球式を持ち、**試し打ちの値と実サーブの値が一致している**
（＝原作のサーブには見積もりのずれが無い）。本作は「サーブもラリーと同じ比率でずらす」
と決めた（2026-07-26 ユーザー決定）ため、**原作には無いずれをサーブに持ち込んでいる。**
②の偽陰性はその直接の帰結。

## ユーザー決定: 試し打ちを「幅」で判定する（2026-07-27）

**原作準拠ではない。本作独自の売りとして意図的に逸脱する**（ユーザー明示）。

いまの試し打ちは**一点**を見ていて、しかも**必ず本物より控えめ**に出る。
実測（候補の判定 4821 件）:

| 試し打ちの判定 | 実際 | 件数 |
|---|---|---|
| 入らない | 入らない | 1413 |
| **入らない** | **入る** | **259**（見送り損） |
| 入る | 入る | 3147 |
| 入る | **入らない** | **2**（ほぼ無い） |

**CPU は下にしか間違えない。** そのため下端〜本物の範囲で判定しても、
結果は「本物で判定する」のとほぼ同じになる（＝手加減が消える）。

**決定**: 一点でなく、**本物を中心に上下へブレる幅**で判定する。
幅のどこかが「入る」なら打つ。

- **上振れ**があるので、CPU は「入る」と勘違いして**ネットに引っかけるミス**をする。
  いまは絶対にやらない挙動。**この試合にアウトは無い**（奥の壁で跳ね返る）ので、
  罰が出るのはネットに引っかけたときだけ
- **幅は1つの数として持つ。** 難易度ごとに違う値を渡せる作りにしておく
- **幅の値の決定は #84（難易度の作り分け）で行う。** 今回は仕組みだけ入れる
- **最強だけ幅ゼロ**（ユーザー決定）。原作の最強は判断を誤らないため

## 確定仕様（Claude Code と Codex が4往復して合意。2026-07-27）

**Codex が最終ラウンドで「合意（これ以上の懸念なし）」と明言済み。**

### 帯の定義

```
step_x = absi(actual_vx) * BAND_STEP_PCT / 100
step_y = absi(actual_vy) * BAND_STEP_PCT / 100
trial_vx = actual_vx + sign(actual_vx) * ix * step_x
trial_vy = actual_vy + iy * step_y
BAND_STEP_PCT = 10
```

- **中心＝実際の打球速度。** 固定倍率 (3/4,18/16)(5/6,14/12)(6/7,1) は**撤廃**する。
  幅方式は倍率方式の**置き換えであって追加ではない**
- **横は進行方向基準**（`sign(actual_vx)` を掛ける）。`+ix` が「速度方向へ強く」、
  `-ix` が「弱く」となり、意味がチームによらず一定になる。
  **これを入れないと必須テスト「左右反転で対称」と矛盾する**（Codex の指摘）
- **縦は素の `iy * step_y`。** 水平反転で `vy` は変わらないので進行方向基準にしない
- **`actual_vx == 0` のときは `ix != 0` の点を評価対象から除外する**（一意性の確保）
- 速度成分が 0 の軸は歩幅も 0 になり、**その軸にはブレが入らない**（仕様として明記）
- 整数除算は被除数が非負なので切り捨て＝床で一意

### 格子の形と段数

- 形は**十字**。`ix == 0` または `iy == 0` の点のみ。点数 = **4k+1**
- 難易度のつまみは**段数 k**（整数）。**`k = 0` が最強＝中心1点＝本物ちょうど**
- **`K_MAX = 3`**（実測済みの範囲。#84 で必要なら測り直して上げる）
- **帯は「連続区間」ではなく「仕様で定めた格子点の集合」。** 格子点のいずれかが
  「相手コートに入る **かつ** ネットを越える」なら有効。連続領域と読める余地を残さない
- **単調性は構造的に保証される。** 歩幅が k に依存しないため、k を増やすと点が
  増えるだけで既存の点は消えない（実測でも破れ0件）

### 「CPUが信じた予測」の選び方（出目3のスコアに使う）

- 距離は**格子座標のマンハッタン距離 `|ix| + |iy|`**。実速度単位でも%でもなく段数で測る
- 走査順を仕様として固定: **`iy` を -k から +k、その中で `ix` を -k から +k**
- 最小距離が複数あるときは**この走査順で最初に見つかった点**

### その他

- **抽選を入れない。** 整数格子の総当たりなので決定論とロールバック安全性は自明
- **バグ修理（倍率撤廃）と幅の追加は設計書を分ける。**
  サーブは `k = 0`（倍率撤廃だけ）で直るため

### テスト必須項目

1. `k = 0` が本物の打球判定と一致する
2. 同じ状態の再実行とロールバック再実行で結果・同期ハッシュが一致する
3. **左右チームを反転しても対称になる**
4. k を上げたとき有効候補の集合が縮まない
5. 非ゼロ k で「格子では有効・本物ではネット衝突・しかも実際に採用」が存在する
6. 最大計算量の上限

### 実測の限界（明記して残す）

- 「十字が効果あたり最良」は**今回比較した全格子と十字の範囲での話**。一般則ではない
- 「vx が vy の約6倍効く」は**4試合・特定格子での観測値**。調整比率ではない
- 実測4試合は「上振れミスが存在する」「vx が有効な軸である」の確認には足りるが、
  **難易度の値を決める根拠としては狭い。値の決定は #84 で改めて測る**

### 幅方式の実測（2026-07-27。判断1343件、出目4を除く934件で評価）

幅は実速度に対する%、帯は9点の標本、スコアは「中心から最も近い有効なずれ」。
**「幅では有効 → 実際に採用 → 本物はネットに衝突」の件数**を数えたもの。

| 軸 | 幅 | アタック | トス | **ネット激突** | 自陣落下 | 成功 |
|---|---|---|---|---|---|---|
| 基準(幅0=本物ちょうど) | 0% | 752 | 182 | **0** | 0 | 752 |
| vy | 10% | 755 | 179 | **6** | 0 | 749 |
| vy | 20% | 764 | 170 | **16** | 0 | 748 |
| vy | 30% | 766 | 168 | **28** | 0 | 738 |
| vx | 10% | 775 | 159 | **36** | 0 | 739 |
| vx | 20% | 785 | 149 | **54** | 0 | 731 |
| vx | 30% | 791 | 143 | **76** | 0 | 715 |
| both | 10% | 779 | 155 | **46** | 0 | 733 |
| both | 20% | 791 | 143 | **68** | 0 | 723 |
| both | 30% | 806 | 128 | **92** | 0 | 714 |

**分かったこと3つ。**

1. **上振れによるミスは実際に起きる。** 幅0で0件 → both30%で92件（アタックの11.4%）
2. **「積極的になるだけで強くなる」は起きない。** アタックは752→806（+7%）だが
   **成功は752→714（-5%）**。差は全部ネット激突。弱くなる方向に効く
3. **自陣落下は全モードで0件。** 失敗の形は「ネットに引っかける」1種類だけ

**幅は vx と vy の両方に入れる。** vy だけだとミスが約1/6しか出ない
（vy10%=6件 に対し vx10%=36件）。倍率方式での②中央の偽陰性も、主因は
**vx が 5/6 に減ること**だった（636518→530431、落下点 309→266、ネットは288）。

**帯は「連続区間」ではなく「仕様で決めた N 点の格子」と定義する。**
実速度は FP 16.16 で②中央の vx は 636518、その30%は 190955 個の整数になるため、
全整数の総当たりは不可能。N 点と定義すれば単調性の証明も不要になる
（間を調べ落としているのではなく、間は仕様上存在しない）。

### サーブは幅ゼロでも直る（重要）

上表の基準行（幅0＝倍率を撤廃して本物ちょうどで判定）だけで、
**サーブの攻撃機会は 11/11 が全部アタックになった**（倍率ありでは 26回中6回）。
**サーブの不具合を直すのに幅は要らない。倍率の撤廃だけで足りる。**
幅は難易度の作り分けのために足すもの。
