# #107 共有シード・Seeded Challenge の遊び方を検討する（課題提起のみ・未設計）

## これは実装タスクではない。ユーザーへの設計質問から始まる

**まず「何のために使うのか」を決めないと設計できない。** 用途が違えば要るものが違う。

- **競技用**（全員同じ条件でスコアを競う）
- **練習用**（同じ場面を何度でも出す）
- **バグ再現用**（不具合の起きた試合をそのまま渡す）

## 背景: 他ゲームの調査（2026-07-28）

ユーザーの指示で調べた。**シードを表向きの値にする文化は確立している。**

- **Slay the Spire の Daily Climb** — 全員同じ種・同じ modifier。運ではなく判断力の勝負になる設計
- **Spelunky の Daily Challenge** — 全世界同じ種、挑戦は1回だけ、リーダーボード付き
- どちらも「良い種を共有する」文化がある

対戦パズル側の調査も #105 の判断材料になった。

- **ぷよぷよテトリス**も時刻ベースで試合開始時に種付けしている。時刻由来は古い作法ではなく現役
- **ぷよぷよ通**は乱数化されたペアの出現順を大きなバッファへ事前生成し、両プレイヤーで共有する。
  「ホストが種を配って両者が同じ系列を辿る」と同じ思想

## 本作で成立しそうな形

2on2 バレーで CPU 戦がある。**同じ種で同じ相手と戦ってスコアを競う**遊び方は成立しそうだ。
#96（KPI ハーネス）とも繋がる。

## 種だけでは足りない

「全員同じ条件」を作るには、種のほかにこれらを揃えて配る必要がある。

1. 種
2. ルール・データのバージョン（`data/rules.json` が変われば同じ種でも別の試合になる）
3. ロスター（4スロットのキャラ）
4. CPU プロファイル（相手の強さ）
5. サーブ側
6. 採点方法（得点差か、所要時間か、被得点か）
7. 挑戦回数と日付の境界
