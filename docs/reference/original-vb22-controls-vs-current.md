## 2. 差分表

### 2.1 入力の割り当て

| 操作 | 原作 (確定) | 現行 | 判定 |
|---|---|---|---|
| 地上・上キー | ジャンプ | ジャンプ | 一致 |
| 地上・横+ボタン | トス3方向 | トス3方向 (自陣後56 / 自陣前157 / 敵陣前291 px) | 一致 |
| 地上・下+ボタン | レシーブ | レシーブ | 一致 |
| 空中・上+ボタン | **アタック** | **ブロック** | **乖離** |
| 空中・下+ボタン | アタック | アタック | 一致 |
| 空中・上下なし+ボタン | トス (地上と少し違う軌道) | トス (敵陣ゾーンへ) | 一致 (軌道は差異) |
| ブロックの入力 | **前キー+ボタン** | **空中の上+ボタン** | **乖離** |

乖離の経緯: 2026-07-20の設計会でブロックの暴発(タスク#47)を解消するため
「空中の上+ボタン=ブロック」の明示入力へ変更した。原作の`前キー`は
地上トスの「前=敵陣へ打つ」と入力が衝突するため避けたと推測される。
判断としては筋が通るが原作準拠ではない。

### 2.2 地上トス

| 項目 | 原作 | 現行 | 判定 |

| 横の狙い | `vx = (目標x - 現在x) / 滞空時間`<br>滞空時間 ≈ `2*abs(vy)/5` (0x5740、記録) | `toss_aim_vx()` = 同じ逆算式<br>`hit_resolver.gd:152` | 一致 |
| 着弾ゾーン | 後=自陣後方 / なし=自陣前方 / 前=敵陣 | 後=56px / なし=157px / 前=291px<br>`hit_resolver.gd:116` | 一致 |
| 縦の高さ | `vy = -24 -18*上 +12*下` (記録)<br>**地上で上フラグが立ち得るかは調査中** | 固定 -520px/s | 調査中 |
| 慣性 (入射速度の反映) | 無し (記録) | **30%を減算**。トス上手キャラのみ0% | **乖離** |
| キャラ差 | 打球強さ = キャラ表0xFA (26〜34) | 全キャラ共通520px/s | 差異 |

注記: 2026-07-25に一度「原作は上下キーでトスの高さを3段階に変える」と
差分表に載せたが、DOCが地上の上キーをジャンプと明記しており、
地上で上フラグが立つ経路を確認していなかったため取り下げた。
`[0xEBC]`(上) / `[0xEBE]`(下) の正体は調査中。

有力な仮説 (未確定): `下`フラグによる `vy = -12` の低いトスが、そのまま
「地上で下+ボタン=レシーブ」の実装である。もしそうなら**原作のレシーブは
「低いトス」であり、トスと同じ目標x逆算式を通っている**ことになる。
これが当たると現行の「レシーブは狙いを持たない」設計が原作と食い違う。

### 2.3 地上レシーブ (2026-07-25 確定)

原作のレシーブは **state 0x0E の専用ハンドラ `0x5BD0`**。
地上トス (`0x56C0`) とは完全に別経路で、**目標x逆算を通らない**。
(ディスパッチ表 `0x7C37: cmp ax,0xe / jmp 0x5bd0` をディレクターが直接確認)

原作の式:

```
vx = (ball_x - player_x) / 2 + rand%5 + 2*(右 - 左)      |vx| <= 4
vy = -40 固定  (来球がアタック球、または入射vy<0 の場合)
   = -打球強さ - |入射vy| / 4   (それ以外)
vy += 3*|vx| + 10*下 - 2*上
```

| 項目 | 原作 (確定) | 現行 | 判定 |
|---|---|---|---|
| 横の狙い | **目標x逆算を通らない。接触オフセット `(ball_x - p.x)/2` で決まる** | 狙いなし。`vx = dir * 40px/s` 固定前進<br>`hit_resolver.gd:431` | 方向性は一致 |
| **前方バイアス** | **無し**。方向は捉えた位置次第で左右どちらにも振れる | **常に前方 40px/s** | ✗ **乖離。ここが無限ループの正体** |
| 乱数 | `rand%5` (0〜+4 の非対称バイアス) | 無し | ✗ 乖離 |
| 左右キーの操舵 | ±2 だけ効く (その後クランプ) | 効かない | ✗ 乖離 |
| 横速度のクランプ | **`\|vx\| <= 4`** | 無し | ✗ 乖離 |
| 縦 | `-40` 固定 または `-打球強さ - \|入射vy\|/4` | -520px/s − 入射vy*30% | 差異 |
| 慣性 | **vy に 25% (条件付き)。vx には一切乗らない** | vx・vy両方に30% | ✗ 乖離 |

**「コントロールが利きません」の正体は4つの機構の複合:**
(1) 目標x逆算を通らない (2) 接触オフセットで方向が決まる
(3) `rand%5` の非対称バイアス (4) 左右操舵が±2でクランプ

**現行の「常に前方40px/s + 慣性30%」は、左右で打ち合うと
不動点 `40/(1-0.3) = 57.1px/s` に収束し、決定論的にネットを越え続ける。**
原作にこの現象が起きないのは、前方定数が無く方向が接触位置と乱数で散るため。

**現行のこの仕様が、CPU同士の無限バンプ往復ループの直接原因である。**
滞空約0.9秒 x 前進40px/s + 慣性で約70px前進するため、ネットから43px以内で
受けると必ず相手コートへ渡る。相手も同じ条件で受けるので永久に往復する。
実測: NORMAL同士1800tickで得点0、空中打撃0、地上タッチ24回。

| 横速度 | **固定** 後ろ`4*dir` / なし`6*dir` / 前`7*dir` (確定) | **目標x逆算**で敵陣ゾーンへ着弾 | ✗ 乖離 |

縦速度の疑義: `original-vb22-physics.md` は §1 で「ボール重力 = +5/frame、
`y+=vy; vy+=g`」、§3 で「サーブ後打ち上げ: vy=-32 / -16」と書いており、
符号規約は**正=下向き**で一貫している。するとスパイクの `vy = -30〜-42` は
強い上向きを意味し、重力5に対して頂点が接触点の約144単位上になる。
接地y=288・ネット上端y=258というコート寸法に対して桁外れであり、
DOC 121行「アタックは高速で」とも整合しない。**0x566E の実命令列を
読み直して符号と state 0x62 の同定を確認する必要がある (依頼済み)。**

## 3. 解決済み (2026-07-25)

1. **`[0xEBC]`(上) / `[0xEBE]`(下) は生のキー入力の写し** (0x49B6 / 0x49CE)。
   派生フラグではない。人間もCPUも同じ変数に書く。
   キー割当は DOC 56〜60行の表と完全一致。
2. **原作のレシーブは目標x逆算を通らない。** state 0x0E の専用ハンドラ `0x5BD0`。
   「コントロールが利かない」は 目標x無視 + 接触オフセット依存 + `rand%5` +
   操舵±2クランプ の複合 (2.3節)。
3. **`0x566E` はスパイクではなくサーブ打ち出しだった。**
   `[0xEB4]` はプレイヤー状態ではなくボール種別で、`0x62` = サーブのトスが上がった状態。
   **本物の空中アタックは `0x6115` にあり、3方向とも下向き。**
   ディレクターが指摘した「vy符号がおかしい」は的中。
4. **アタックの vx は目標x逆算を通らない。** `4/6/7 * dir` の固定値。
   逆算を通るのは地上通常打 (0x56D9) と空中通常打 (0x649F) だけ。
5. **「アタックはアタックで返せません」**: `0x610B` の
   `cmp [0xEB4],0xA; jl` でアタックスイング分岐に入れず、通常の空中トス速度が乗る。
   その直後に威力100%のダメージを食らって state 7 (吹っ飛び) になる。
   **「打ててはしまうがトスにしかならず、自分は満身創痍」。**
6. **「反射毎に半減」は誤り。** `[0x10DA] /= 2` は特定キャラの空中下必殺技2箇所だけ。
   実際の軽減は**被弾側の状態による倍率** (レシーブ ×0.4 / ブロック ×0.5 / その他 ×1.0)。
7. **CPU思考ルーチンと GAME LEVEL は完全に判明した。**
   → `docs/reference/original-vb22-cpu-ai.md` (タスク#62 完了)

### 追加で判明した重要事項

- **原作の空中トスは自陣狙い** (目標x = `76 - (10 + 26*後)*dir` → team0 で 66 / 40)。
  敵陣送りは前キー時のみ。**現行は空中の全トスが敵陣行きで、ここが決定的に乖離している。**
  設計会仕様が「空中から自陣へつなぐ手段がない」と懸念に記録した項目は、
  **原作には存在していた。**
- **原作にも慣性はあった。** 下入力レシーブは入射vyの25%を取り込み、
  ブロックは持ち越す。先行文書の「慣性0%」は誤り。
  **ユーザーの実機観察#15「慣性はある」が正しかった。**
- **原作は標準2発で気絶。** 現行は4発。
