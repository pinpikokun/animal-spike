# 原作 VB22 の CPU 思考ルーチン (逆アセンブル確定)

2026-07-25、タスク#62 (ユーザー指示「CPU調整再開前に必ず実施」) の成果。
`VB22.EXE` を capstone で全逆アセンブルし、CPU思考ルーチン `cpu_ai`(0x7DE8) を
同定して読み下した。確度は特記なき限り「高」。

成果物 (再生成可能): `C:\work\PC98\vb2211-analysis\`
`vb22-cpu-ai.asm` / `vb22-cpu-analysis.py` / `vb22-cpu-symbols.md` / `snippets/`

## 0. 要点 (これだけ読めば足りる)

**原作CPUは「良い手を探す」のではなく「悪い手を弾く」設計。**
候補を乱数で作り、弾道シミュレータ `predict()` で棄却する。この非対称性が、
8086の貧弱な予算でもラリーが破綻しない理由。

リメイク側が「最善手を評価する」方向で作ると、評価関数がレシーブに収束して
アタックが出なくなる。**まず役割で攻撃を強制し、次に仮想打球テストで
安全性を検証する** — この順序が要点。

## 1. CPUと人間の境界

判別は `P_ctrl[idx] = byte[DS:0x0E64]`。`0..3` = 人間のキーセット番号、`4` = CPU。
分岐は `player_update`(0x494A) のたった1か所:

```
4988  cmp byte [P_ctrl+bx], 4
498d  jne 4992
498f  jmp 4a64          ; → CPU
4992  ...               ; → 人間: KEY[] のビットを IN_* へ展開
4a69  call 0x7de8       ; cpu_ai(idx)
4bce  jmp 0x7bc8        ; 状態機械へ (CPUと人間を区別しない)
```

**CPUは仮想パッドを持たず、人間と同じ入力グローバルへ直接書く。**

| DS | 名前 | 意味 |
|---|---|---|
| 0x0EBC / 0x0EBE | `IN_up` / `IN_dn` | 上 / 下 |
| 0x0E80 / 0x0E71 | `IN_left` / `IN_right` | 左 / 右 |
| 0x0EB2 / 0x115B | `IN_fwd` / `IN_back` | 相手コート方向 / 自コート方向 |
| 0x10E6 / 0x0E70 | `IN_btn_edge` / `IN_btn_hold` | ボタン押下瞬間 / 押しっぱなし |

チーム構成: `side = idx & 1` (0=左, 1=右)、相方 = `idx ^ 2`、敵 = `idx ^ 1`。

## 2. 知覚は「着弾x」1個だけ

`predict()`(0x1EF2) は実物理と完全同一式で先読みし、**着弾xだけを返す**
(フレーム数は返さない)。先読み上限30フレーム、超えたら `-1`。
壁反射・ネット判定・重力半減状態まで本物と同じ式を使う。

**CPUが持つ情報はこの1スカラーのみ。**

## 3. 役割分担 — ここが「まともに見える」中核

### 3.1 前衛/後衛 (`P_aiflag` bit0)

0x7E31 で「相方より前か後ろか」を毎フレーム更新し、
0x7E9D で `aitick % 8 == 0` ごとに相方と入れ替える。
**2人は常に前衛/後衛に分かれ、定期的にスワップする。**

### 3.2 アタッカー役 / ブロッカー役 (`P_aiflag` bit1 / bit2)

**ラリーごとに9通りから抽選** (0xBBCC, main内):

```
bbcc  RND = RND*2 + 1
bbd5  r = RND % 9
bbe2  ; r=0: a がアタッカー+ブロッカー、b がブロッカー
bbf6  ; r=1: a だけ
bc04  ; r=2: 逆
bc1e  ; r=3: b がアタッカーのみ  ... 全9通り
```

**両方がアタッカーになる組み合わせは限られる。跳ぶのは原則ひとり。**
これが「二人とも拾いに行って誰も攻めない」を構造的に潰している。

### 3.3 ボールを取る担当 (0x8319)

```
8323  cmp word [team_touch+bx], 0
8332  ; 1打目 → 二人とも予測着弾へ突っ込む (idx>=2 は +4 ずらす)
8335  ; 相方が動作中 → 自分が取る
833b  ; myDist  = |P_x[me]       - ball_x|
8355  ; partner = |P_x_prev[相方] - ball_x|
8372  ; 相方が近い → 自分はネット際 (76 - sidesign*16) へ退く
8376  ; 自分が取る → 目標 = pred - (sign(ball_vx)*2 + 2)*sidesign  (進行方向へ先回り)
83fb  ; 3回触っていたら動かない
```

相方と8px以内で `ball_state<=9` かつ相方もCPUなら自分は打たない (0x8229)。

### 3.4 待機位置 (相手コートにボールがある間, 0x8406)

`aitick % 9` × 前後役のテーブルで自コート中央からのオフセットを決める:

| 相方の状態 | `aitick%9` | オフセット |
|---|---|---|
| 動作中 | 0–4 / 5–6 / 7–8 | 40 / 64 / 16 px |
| 待機中 | 0–3,8 / 4–5 / 6–7 | 前後役で (20 or 60) / (35 or 70) / (15 or 40) px |

ブロック寄せ (0x85F8): 敵が空中 + 予測着弾がネット±40px + ボールが相手コート側
→ 目標をネットから8pxへ書き換え。

**待機中に目標位置へ着いたら `IN_dn = 1` を出し続ける (0x880D)。
つまり原作CPUは常にレシーブ構え(しゃがみ)で待っている。**

## 4. 3タッチの組み立て

### 4.1 枠組みは物理側が強制する (0x56C0)

地上打撃は**入力ではなくチームのタッチ数**で打ち分けが変わる:

```
56c0  cmp byte [IN_fwd], 0
56c7  jmp 57a8                      ; 前入力 → 相手コートへ返す
56cf  cmp word [team_touch+bx], 2
56d6  jmp 57a8                      ; ★3打目は自動的に相手コートへ
56d9  ; ---- 1〜2打目は自コートへのトス ----
571d  ; 目標x = 76 - sidesign*(28*IN_back + 10)
      ;   左コート: IN_back無し=66(自陣前方) / IN_back有り=38(自陣後方)
5740  ; vx = (目標x - ball_x) / (2*|vy|/GRAV) 、|vx| <= 3 にクランプ
```

**1〜2打目は必ず自コートへ着地目標付きでトス。3打目は必ずオーバーネット。**
CPUは方向修飾しか選ばない。

オーバーネット枝 (0x57A8) には目標xが無く `vx = (fwd - back + 5) * sidesign` の固定速度。
**原作に「相手の居ない所を狙う」配球ロジックは存在しない。**

### 4.2 CPUの地上判断 (0x922A)

```
9295  cmp word [ball_state], 0x63    ; 味方が上げたトスか
929c  ; RND%8 < 2 (25%) → IN_dn=1                (下打ち)
92b2  ; RND%8 < 6 (50%) → IN_up=1, IN_fwd=1      (上+前=強打/必殺技)
      ;      残り 25%   → 素のトス
92ce  ; skill >= RND%3 かつ team_touch==1 → IN_fwd=1  (2打目で返す)
9301  ; ネット32px以内 + 能力ゲート + キャラ0..4 → IN_up=1 (地上必殺技)
93b0  ; どれにも当たらなければ RND 2/3 で IN_back=1
      ;   = 自コート後方への深いトス ← お膳立て
```

## 5. ジャンプ発火条件 (0x8824)

```
8824  しきい値 = 10 (相手のスパイク ball_state==0x62 なら キャラ別 0x1A / 4 / 0xA)
8863  |P_x[me] - ball_x| <  0x14    (横20px以内)
887f  |ball_vx|          <  5       (横に流れていない)
888e  |ball_vy|          <  しきい値 (頂点付近)
889d  ball_y             <  0xc8    (=200、十分高い)
88a5  → IN_up = 1
88d0  ただし P_aiflag bit1 (そのラリーのアタッカー役) を持つ者だけ
88ef  かつ 難易度ゲートを通過したときだけ
```

**「頂点付近・横に流れていない・十分高い」のAND。悪い球には跳ばない。**

## 6. ★仮想打球テスト (0x93CA) — 原作CPUの心臓部

**ボールの速度と状態を一時的に書き換えて `predict()` を呼び、
その打ち方が相手コートに入るかを最大3通り試す。**

```
945f  ; ★退避: ball_vx / ball_vy / ball_state を保存
9471  ; 試行1: vx = 3*sidesign, vy = 0x12, state = 0x0A   (ゆるい攻撃)
94b1  call predict
94cc  ;   相手コートに入る + RND%2 + skill>=2 → 採用
94f2  ; 試行2: vx = 5*sidesign, vy = 0x0E
952c  ;   (相手スパイク返しなら vx=6*sidesign, vy=4 or 20)
957a  call predict
9596  ;   入る → RND%2 か skill<=1 で採用
95bf  ;   skill<2 なら諦めて IN_up/IN_dn を消す → ただのトスに落とす
95d4  ; 試行3: vx = 6*sidesign, vy = 4  (最速フラット球)
962c  call predict
9648  ;   入らない → IN_up=0, IN_dn=0  ★アタックを取り下げてトスにする
      ;   入る     → IN_fwd=1
96d1  ; ★復元
```

打ち方の初期選択は `RND%3 != 0` で下(2/3)、そうでなければ上(1/3)。

**「どの打ち方でも相手コートに入らない」と判定したらアタックを取り下げる。
これがネットミス・アウトを構造的に防いでいる。**

## 7. GAME LEVEL (難易度)

変数 `byte[DS:0x0E90]`、値域 0..3 (EASY / NORMAL / HARD / SUPER)。
全参照10か所のうち**ゲームプレイに効くのは 0xB561 の1か所だけ**。

```
b554  bx = idx ^ 2                  ; ★相方を見る
b55a  cmp byte [P_ctrl+bx], 4
b561  mov al,[OPT_LEVEL]            ; 相方もCPU → GAME LEVEL
b568  mov ax, 3                     ; 相方が人間 → 常に 3 (最強)
b56e  mov byte [P_skill+bx], al
```

**1人プレイでは味方CPUは常に SUPER 相当。GAME LEVEL は敵チームにしか掛からない。**

`P_skill`(0x115C) は 0x7F27 の switch で能力ゲート5個+反応ウェイトに展開:

| 対象 | EASY | NORMAL | HARD | SUPER |
|---|---|---|---|---|
| 攻撃球へのレシーブ | `aitick%8==0` | `aitick%4==0` | `aitick%3<2` | 常時 |
| スパイク用ジャンプ | `aitick%8==0` | `aitick%2==0` | `aitick%3<2` | 常時 |
| 地上必殺技 | `aitick%8==0` | `RND%4==0` | `aitick%3<2` | `RND%4<3` |
| ブロック用ジャンプ | **常に不可** | `aitick%6==0` | `aitick%3<2` | 常時 |
| 特定硬直の無視 | 不可 | `RND%4==0` | `RND%3==0` | `RND%2==0` |
| 反応ウェイト | 1 | 2 | 4 | 8 |

反応遅延の実体 (`team_hitcd[side]` は打球時10、1/フレーム減算):

| | 思考全停止 | 移動停止 |
|---|---|---|
| EASY | 7 フレーム | 9 フレーム |
| NORMAL | 6 フレーム | 8 フレーム |
| HARD | 4 フレーム | 6 フレーム |
| SUPER | 0 フレーム | 2 フレーム |

`P_skill` は判断の質にも直接効く: 2打目で返すか (`skill >= RND%3`)、
仮想打球テストの採用/放棄、`ball_state==6` の球を skill>=2 はわざと触らない。

**判定: 「能力を削る」方式。狙いにノイズを注入する箇所は一切ない。**
乱数の使い方自体は全レベル共通で、レベルが変えるのは「乱数ゲートを通す確率」。

**わざとミスするロジックは存在しない。** CPUが弱く見えるのは
(i) 反応遅延、(ii) 能力ゲートによる発火間引き、(iii) skill<2 が攻撃を諦めること
の3つだけ。**「失敗を混ぜる」のではなく「成功を減らす」設計。**

## 8. サーブ (0x80FC)

```
8104  inc word [bx+0x114e]
810c  cmp ax, 9
8111  jmp 99df                  ; 9フレーム未満なら何もしない
8122  mov byte [IN_btn_edge], 1 ; ★ボタンを押すだけ
```

**方向入力を一切出さない。狙いを散らさない。**
サーブ待ち中は `x = 0x90*side + 4` に固定。
`team_touch` が番兵 0x63 なので地上打撃は自動的にオーバーネット枝を通る。
実質 `vx = 5*sidesign`, `vy = -38` の固定弾道。**サーブミスを起こす分岐は無い。**

## 9. リメイクへの示唆

### そのまま借りるべき

1. **アタッカー役をラリー単位で抽選し、跳ぶのは原則ひとり。**
   全員が常に「拾いに行く」評価をしていると誰も攻撃姿勢に入らない。
   役割をラリー開始時に確定させ、フレーム単位の評価より優先させる。
2. **仮想打球テスト。** 「この打ち方をしたら入るか」を実simで前方シミュレートして決める。
   **入らないなら攻撃をやめてトスに落とすフォールバックは必ず持たせる。**
   原作が3通りしか試せなかったのは8086の予算制約であって設計思想ではない。
3. **トスに固定の着地目標を持たせる** (原作: 自コート前方66 / 後方38)。
4. **ジャンプ条件を「頂点付近 AND 横速度小 AND 高さ十分」のANDに絞る。**
5. **難易度は反応レイテンシと能力ゲートで作る。** 狙いを乱数でブレさせない。
6. **待機中はレシーブ構え(しゃがみ)で立つ。**
7. **前衛/後衛の分担と定期スワップ。**

### そのまま移植すべきでない

- **`aitick` を使ったゲート。** 「打球ごとに += RND」というカウンタの mod が
  擬似乱数代わりになっている8086の小細工。決定論simではシード付き乱数か
  明示的なクールダウンタイマーへ置き換える。
- **30フレームの先読み上限と「着弾xのみ」という貧しい知覚。**
  60fpsの決定論simなら着弾x・着弾時刻・軌道最高点まで安く取れる。
  ただし「CPUに与える情報量」を難易度パラメータにするのは有効。
- **配球ロジックの不在。** リメイクは目標xを直接指定できるので
  「相手の薄いところを狙う」評価を足す余地がある。優先度は低い
  (原作のラリーが回っていた事実が「配球が無くても成立する」ことの証明)。
- **`team_hitcd` を移動凍結に流用する形。**
  反応遅延は「入力を N フレーム遅れで流す」方が素直。

## 10. 未解明と原作のバグ

未解明 (確度 低〜中): プレイヤー状態値の完全な意味、`ball_state` の完全な分類、
`[0x117E]` (`ball_flightsub`) の 0x12 の意味、`0x4CF3` の `predict()` 呼び出し、
`P_aiflag` bit3 の用途、`IN_btn_hold`(0x0E70) が CPU 経路でクリアされない件
(0x4964 の初期化リストに無いのは確認済み。実挙動への影響は静的解析では未断定)。

**原作のバグ (確度 高)**: 0x8617 / 0x8628 のブロック寄せ判定は敵プレイヤーを
`bx = idx+1` と `bx = (idx^2)+1` で求めている。`idx==1` のとき後者、`idx==3` のとき
前者が `4` になり、`P_y[4]` すなわち `[0x117E]` を y 座標として読む。
**右コート側 (idx 1,3) のCPUはブロック寄せの判定が片方壊れている。**
移植時に「原作準拠」として持ち込まないこと。
