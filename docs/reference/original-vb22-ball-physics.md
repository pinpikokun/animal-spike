## 0. 先行記録の訂正 (重要)

### 訂正1: `[0xEB4]` はプレイヤー状態ではなく「ボールの種別」

- `0x63` = サーブ待ちのボール (サーバーの手元)
- `0x62` = サーブのトスが上がった状態のボール
- `0` = 通常球、`1`〜`0x0E` = 必殺技/アタック球

したがって **`0x566E` は「スパイク」ではなく「サーブ打ち出し」、
`0x562D` は「サーブのトス上げ」である。**
先行記録の「スパイク(state 0x62, 0x566E): vy = -38 -4*上 +8*下」は
**サーブの式**であって、スパイクの式ではない。

これが「スパイクの vy が上向きに見える」という矛盾の正体だった。
サーブはコート外 (x≒4〜8) から相手コート深部へ届く大きな山なりなので、
vy = -38 (上向き) で完全に筋が通る。

| なし | -38 | x=134, 18フレーム | y=96 |
| 上 | -42 | x=148, 20フレーム | y=62 |
| 下 | -30 | x=106, 14フレーム | y=155 |

### 訂正2: 本物の空中アタックは `0x6115`。3方向とも下向き

**確度: 高。** 詳細は第2節。

### 訂正3: 「攻撃威力は反射毎に半減 (0x623D)」は誤り

`[0x10DA]` を2で割っているのは **特定キャラの空中下必殺技2箇所だけ**
(0x623D = キャラ5、0x627F = キャラ7)。壁・ネット反射とは無関係。
**「反射毎に半減」という規則はコード上に存在しない。**

軽減は**被弾側の状態による倍率**として実装されている。第5節参照。

## 1. 座標系と積分

```
整数word、固定小数点なし。1フレーム = 1ステップ。
x: 壁 4 .. 148、ネット中心 76、ネット帯 72..80
y: 下向き正、ネット上端 258、床 291、プレイヤー接地 288
ボール:     x += vx ; y += vy ; vy += 5 ; vy = min(vy, 32)
プレイヤー: vy += 6
dir = +1 (左チーム) / -1 (右チーム)   ; DS:0x42 = {+1, -1}
```

**除算はすべて x86 `idiv` = 0方向切り捨て。**
Python の `//` (床除算) で移植すると負値でズレる。

### 入力変数 (すべて 0/1 のフラグ)

PC-98キーマトリクス走査 (0x0A46) の結果を `[0x1164 + ctrl*2]` に格納し、
`playerUpdate` (0x494A) がビット展開する。**人間もCPUも同じ変数に書く。**

| DS | 名前 | 由来 |
|---|---|---|
| 0x0EBC | 上 | 生キー bit0 (0x49B6) |
| 0x0EBE | 下 | 生キー bit1 (0x49CE) |
| 0x0E80 / 0x0E71 | 左 / 右 | 生キー bit2 / bit3 |
| 0x0E70 / 0x10E6 | ボタン押しっぱなし / 押下エッジ | 生キー bit4 |
| 0x0EB2 | **前** (敵陣方向) | 0x4A01でチーム相対に変換 |
| 0x115B | **後** (自陣奥方向) | 同上 |

キー割当は DOC 56〜60行の表と完全一致 (W X A D SHIFT / 8 2 4 6 0 / U M H K B / ↑ ↓ ← → XFER)。
先行記録が「補正」と呼んでいたものは**後キー**だった。

### 2.1 空中アタック (0x6115) — 3方向とも下向き

```
610b  cmp word [0xeb4], 0xa       ; 来球がアタック/必殺技球なら不可
6141  mov word [bx+0xe78], 4      ; state 4 = 空中アタック
6159  imul word [bx+0x42]         ; vx = 6*dir
6160  mov word [0x1132], 0xc      ; vy = +12   ← 下向き
6166  cmp byte [0x115b], 0        ; 後キー?
617a  mov word [0x1130], 4*dir ; mov word [0x1132], 0x10  ; vy = +16 (鋭角)
6186  cmp byte [0xeb2], 0         ; 前キー?
```

打点 x=68, y=225 からの着弾 (数値シミュレーション):

| 入力 | vx | vy | 着弾x | 到達 |
|---|---|---|---|---|
| 後 | 4*dir | **+16** | 84 | 4フレーム |

### 2.2 ★空中トスは自陣狙いである

```
空中通常打 (0x6449): 目標x = 76 - (10 + 26*後)*dir
   → team0 (左コート): 前方 66 / 後方 40
   → team1 (右コート): 前方 86 / 後方 112
```

**原作の空中トスは味方へのトス (自陣狙い)。敵陣送りは前キーを押した時だけ。**
DOC 114〜115行「空中でも上下キーを押さずに打つとトスになりますが、
すこし上記の軌道と変わります」と一致。

### 2.3 目標x と入力の対応 (DOC と完全一致)

| 入力 | 経路 | 目標x (team0) | 目標x (team1) | DOC 110-112行 |
|---|---|---|---|---|
| 方向なし | 逆算 | **66** | **86** | 「自分のコートの前方」 |
| 後 | 逆算 | **38** | **114** | 「自分のコートの後方」 |

コート系は壁 4〜148、ネット中心 76。**66 はネットから10単位＝ネットのすぐ手前**、

### 2.4 目標x逆算の「ゆるさ」

滞空時間 `T = 2|vy| / 5` は「同じ高さに戻るまで」の時間であり、床までではない。
**そのため実着弾は目標より数単位オーバーする** (打点 y=270 で目標66 → 実着弾65〜70)。
原作のトスの「ゆるさ」はこの誤差が正体。

## 4. ★レシーブ — 「コントロールが利かない」の正体

### 4.0 ハンドラの確定 (ディレクターが直接確認)

別の解析が「レシーブは `0x56C0 → 0x56D9` 経路」と主張したため、
状態ディスパッチ表 `0x7BC8` を直接読んで決着させた。

```
7c37  cmp ax, 0xe
7c3a  jne 0x7c3f
7c3c  jmp 0x5bd0      ← state 0x0E → ハンドラ 0x5BD0
```

**レシーブ (state 0x0E) の専用ハンドラは `0x5BD0` で確定。**
`0x56C0` は `0x5548` (state 2 / 0x0D = 地上打撃) の中にあり、トスの経路である。

ディスパッチ表の主要な対応:

| state | ハンドラ | 意味 |
|---|---|---|
| 0, 0x63 | 0x4BD2 | 地上待機 / サーブ待ち |
| 1, 0x13 | 0x5136 | 空中 / ボール保持 |
| 2, 0x0D | 0x5548 | 地上打撃 (トス・サーブ打ち) |
| 3, 0x0C, 0x11 | 0x5ECD | 空中打撃 / ブロック |
| 4, 0x12 | 0x68DC | 空中アタック / ブロック被弾 |
| 5, 6 | 0x6B6E | 横っ飛びレシーブ |
| 7, 0x0F | 0x6F62 | 吹っ飛び |
| 8, 0x10 | 0x70E0 | — |
| 9 | 0x72EA | ダウン |
| 0x0A | 0x744A | — |
| 0x0B | 0x771E | — |
| **0x0E** | **0x5BD0** | **レシーブ構え** |
| 0x14 | 0x5EC0 | ボールキャッチ |
| 0x15 / 0x16 / 0x18 | 0x7930 / 0x7A94 / 0x7BC0 | — |

### 4.1 state 0x0E への入り方 (0x4E58)

```
4e66  cmp byte [0xebe], 0     ; 下キー
4e6d  cmp word [0xeb4], 0x61  ; かつボール種別 < 0x61 (サーブ球でない)
4e74  mov ax, 0xe             ; → state 0x0E
4e7a  mov ax, 2               ; それ以外 → state 2 (通常トス)
```

**ボタン押下エッジで一度だけ入る (押しっぱなしでの維持ではない)。**
スプライトは `SPR_BASE + 6` (先行調査の「セル6＝レシーブ構え」を確認)。
接触条件: `|ballx - px| < 9`, `|bally - py| < 40`, ボールが自陣側, クールダウン<10。

打球式 (0x5CB7):

```
vx0 = (ballx - px) / 2 + (rand % 5) + 2*(右 - 左)

if 来球種別 0x0A..0x0D  または  入射vy < 0 (上昇中):
    vx = vx0 / 2
    vy = -40                        ; 固定
else:
    vy = -打球強さ - |入射vy| / 4
    vx = vx0

vy += 3*|vx| + 10*下 - 2*上
if |vx| > 4: vx = sgn(vx) * 4
プレイヤー vy = -16 (小さく跳ねる)、ボールは player.y - 16 にスナップ
```

**「コントロールが利かない」は4つの機構の複合:**

1. **目標x逆算式を一切通らない** (`idiv` による逆算が無い)
2. `vx` は **ボールとプレイヤーの接触オフセットの1/2** — 「どこで捉えたか」だけで方向が決まる
3. **`rand % 5` の加算** (0〜+4、**符号が偏った非対称バイアス**)
4. 左右キーによる操舵は **±2 だけ**、しかも条件により1/2され、最終的に ±4 にクランプ

`vy` も `-40` 固定か `-強さ - |入射vy|/4` で、高さも選べない。

**つまり「ランダム化」と「目標x無視」の両方が実装されている。単なる乱数散らしではない。**

### 4.1 横っ飛びレシーブ (state 5/6)

発動条件 (0x4D14)。`[bp-2]` は **弾道シミュレータ 0x1EF2 が返す落下予測x**:

```
右飛び(state 5): (右キー AND px+8 < 予測x < px+0x18) OR (px+0xD < 予測x < px+0x18)
左飛び(state 6): (左キー AND px-0x18 < 予測x < px-8) OR (px-0x18 < 予測x < px-0xD)
→ player.vy = -14, player.vx = ±ダッシュ速度, スプライト cell 3 / 27
```

打球式 (0x6CAA)、接触スプライト cell 11:

```
t  = (タッチ数 <= 1) ? 0 : 1
vx = ((2*t + 1)*dir + 右 - 左) * 2 + (rand % 7) - 3
if |vx| > 5: vx = sgn(vx)*5
vy = 2*|vx| - 33
```

**ダメージ軽減は無い** (state 5/6 は 0x39C2 の軽減分岐に入らない)。
横っ飛びは届く範囲を広げるだけで、アタック球を受ければ満身創痍。確度: 中 (要実機確認)。

## 5. ダメージ

```
攻撃威力 [0x10DA] = 打った側のキャラ表 0x11A の値 (打つ瞬間に設定、0x55D1)
被弾: スタミナ [bx+0x1100] -= 威力 × 倍率
```

軽減は **被弾側の状態**で決まる (0x39C2 内、8087エミュレータ経由の double 演算):

| 被弾時の状態 | 倍率 | 遷移先 | ノックバック |
|---|---|---|---|
| 0x0E レシーブ構え | **×0.4** | state 0x0F | `vx = -4*dir` |
| 0x11 ブロック | **×0.5** | state 0x12 | `vx = -3*dir` |
| その他 | **×1.0** | state 7 (吹っ飛び) | `vx = -5*dir`, `vy = -10` |
| スタミナ ≤ 0 | — | state 9 (ダウン)、スタミナ全回復 | — |

DOC 129行「レシーブはダメージを大幅に減らす」= 0.4、
DOC 137行「ブロックはダメージを半分ぐらいに減らせる」= 0.5。**DOCとコードは一致。**

## 6. ラリー規則

タッチカウンタ = `[0x113A + team*2]` (word×2)。

```
0x39C2 (ボール接触時、全打球共通):
  39d1  and ax, 1                     ; team = playerIdx & 1
  39f3  inc word [bx + 0x113a]        ; 打ったチームのタッチ数 +1
  3a08  mov word [bx + 0x113a], 0     ; ★相手チームのカウンタを0リセット
```

- **3タッチ制限**: 0x4B2D `cmp [bx+0x113a], 3 ; jge → 打撃不可`。
  3回打つと自チームの誰も触れなくなり、落ちて失点。
  **明示的なファウル処理は存在しない** (触れなくなるだけ)。
- **ブロックもカウントされる** (state 0x11 の打球処理 0x60D4 が 0x39C2 を呼ぶ)。
  DOC「ブロックも1回打ったことになる」と一致。
- **同一人物の連続打は許可**。「直前の打者」を記録する変数が存在しない
  (チェックの不在として実装)。制約は個人クールダウン `[0x114E]` (打つと10、
  10未満でないと打てない) とチーム単位の再打ロック `[0xE72+team*2]` (約4フレーム) のみ。
- **番兵値 0x63 (=99)**: サーブ打ち出し等で `[0x113A][team] = 0x63` を書き込み、
  そのチームを「打ち止め」にロックする。

### 6.1 得点判定 (0x4844)

```
4844  cmp word [0x10c6], 0x123   ; ボールy >= 291 (床)
      バウンド処理 vy = (-vy + 6)/2 、|vy|<8 で停止
490d  cmp word [0x112c], 0       ; まだ得点確定していないなら
491e  inc word [0x112c]
4922  cmp word [0x10c2], 0x4c    ; 落下地点が x < 76 なら
4930  mov byte [0x10dc], al      ; 得点したチーム = 反対側
```

- **アウト判定は存在しない。** 壁 x=4/148 で反射
  (`|vx|>1 → vx = -vx/2` 、`|vx|==1 → vx = -vx`)。
  DOC「コートの左右は壁でボールは跳ね返る。アウトはない」と一致。
- ネット側面 72/80 も同じ反射則。ネット上端 258 の跳ねは `vx = vx*4`、`vy = vy/2`。
- ボール落下速度上限 32。

### 6.2 アタック球を通常打で返すと散る (0x5778)

地上通常打で、来球種別が `9 < 種別 < 0x14` (アタック球/必殺技球) のとき:

```
vx += (rand % 5) - 2 ;  vy += rand % 16
```

**「アタック球をトスで返そうとすると散る」。**
DOC「トスなどをするとダメージを食らう」に加えた第2のペナルティ。

### 6.3 「アタックはアタックで返せません」の実装

1. 0x610B の `cmp [0xEB4],0xA; jl` により、来球がアタック球/必殺技球のときは
   **アタックスイング分岐に入れない**
2. 代わりに通常の空中トス速度がボールに乗る
3. その直後 0x652C で 0x39C2 が呼ばれ、状態が 0x0E でも 0x11 でもないため
   **威力100%のダメージ**を食らい state 7 (吹っ飛び) になる

**「打ててはしまうがトスにしかならず、自分は満身創痍」。** DOCと整合。

## 7. ブロックの入力条件

DOC 135行「空中、または地上にネット際で前キーを押しながらボタン」——**コードも同じ**。

地上ブロック (state 0 → 0x11、0x4C54):

```
ボタン押下エッジ AND |player.x - 76| < 10 (ネット際)
               AND 前キー != 0
               AND (ボールが相手側 OR ボールが自分に向かって飛来)
→ state = 0x11, player.y -= 12, vy = -12, vx = 0
```

空中ブロック (state 1 → 0x11、0x5202):

```
ボタン押下エッジ AND 前キー != 0
               AND 上キー == 0 AND 下キー == 0
               AND 自チームのタッチ数 == 0     ← 1タッチ目限定
→ state = 0x11
```

**上キーではなく前キー。** ネット際判定は地上のみ。空中は「自チーム未接触」が追加条件。

## 8. サーブ

2段階 (トス上げ → 打つ)。ラウンド初期化 0xBC76 で
サーバーの state = 0x63、ボール種別 = 0x63、ボールx = サーバーのx (コート外)。

第1打 (トス上げ、0x562D) でボール種別が 0x62 へ遷移。
**サーバーはこの時点で初めてジャンプ可能になる** (0x4EA4)。

第2打は3経路:

| 経路 | 条件 | vx | vy |
|---|---|---|---|
| 0x566E 地上 | state 2 | `(7 + 前 - 後)*dir` | `-38 - 4*上 + 8*下` |
| 0x62E2 空中 (ジャンプサーブ) | state 3 | 上下あり `6*dir` / なし `(7+前-後)*dir` | 上下あり `4 - 8*前 + 2*後` / なし `-24` |
| 0x6C3D 横っ飛び | state 5/6 | `(2*前 + 2 - 後 + rand%5)*dir` | `-28 - 6*上 + 8*下` |

**プレイヤーは狙いを付けられる** (上下で高さ、前後で速度)。目標x逆算は通らない。

### 8.1 サーブのネット接触 (0x47DA)

OPTION値 `[0x112F]` による3分岐:

- `0` → SE 7、得点確定、相手チームへ得点 (**サーブミスで失点**)
- `2` → SE 6、やり直し扱い
- `1` → 何もしない (触ってよい)

DOC「サーブはネットに触れてはいけない (変更可能)、通常は触れてもよい」と一致。
確度: 中 (OPTION値とメニュー表記の対応は未確認)。

## 9. DOC とコードの食い違い

1. **DOC 107-112行 (トス) は左右方向しか書いていないが、コードは上下キーも読む。**
   地上トスの `vy = -強さ - 4*ボタン - 2*(上+後) + 16*下`。
   ただし下+ボタンは state 0x0E (レシーブ) へ行くため、このパスで下が立つのは特殊ケース。
   上キーは地上ではジャンプだが、**打撃モーション中 (state 2) に上を押し、
   同じフレームでボールに接触すれば上フラグが立ち得る**。確度: 中 (実機未検証)。
   ただし上フラグが1のときは 0x5855 で**必殺技分岐**に入るため、
   実際には「上+ボタン = 地上必殺技」として消費される。
2. DOC は「サーブは1回で入れなければならない」と書くが、コードは2段階。
   球種が 0x63→0x62 に不可逆遷移するためトスはやり直せない。矛盾ではないが粒度が違う。
3. DOC 137行「ブロックはダメージを半分ぐらい」→ コードは正確に 0.5。
4. DOC 129行「レシーブはダメージを大幅に減らす」→ 0.4。
   ブロック (0.5) との差はわずか 0.1。DOCの語感とコードの実数には温度差がある。
