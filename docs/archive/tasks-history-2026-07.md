# 経緯

## この一覧を作った理由（2026-07-25）

ユーザーの指摘で仕様書・原作資料・コード全体を横断で洗い直したところ、
**#82 から #98 までの17件が、文書に書いてあるのにタスクとして追跡されていなかった**
ことが判明した。特に影響が大きいのは次の3件。

- **#82 仮想打球テスト** — 原作資料が「CPUの心臓部」「そのまま借りるべき」と書いている中核機構
- **#88 乱数方式** — 業界標準を調べずに選んだ設計
- **#89 キャラ差3軸** — 式だけ通っていて実データが無く、全キャラ同一で動いていた

## 優先度を組み直した理由（2026-07-25、同日）

最初の版はネット対戦（#25, #72）を P1 に置いていた。根拠は M0 の設計書が
ネットコード検証を「不合格なら Unity へ移行する撤退ゲート」として前倒ししていたこと。
**しかしこれは Claude Code が古い計画をそのまま引き写したもので、
いまの状況で妥当かを検証していなかった。**
既に Godot の上に大量に作っており、いま不合格でも撤退は現実的でない。
ゲームの中身を P2 へ、ネット対戦を P4 へ移し、土台（#86, #88）だけを P1 に残した。

## 根拠を確認せずに書いた項目の訂正（2026-07-25、同日）

ユーザーの求めで全項目の根拠を洗い直したところ、
**現物を確認せずに書いた記述が2件見つかった。**

- **#86**: 「salt=17 が重複」と書いたが、現在のコードに重複は無い。
  2026-07-19 の仕様書の古い指摘をそのまま書き写していた。
  調べ直したところ別の実害（ハッシュ実装が2種類、`SALT_RECEIVE` が本体で未使用）が見つかり、
  そちらへ書き換えた。
- **#98**: 「初回は全キャラ全ランクCで性能差がほぼ無い」と書いたが、
  実際は13体中5体が既に個別ランクを持ち、付与能力も割当済み。

加えて会話中に **#35 を「劣勢なら手加減する仕組み」と説明したのも作り話**で、
調査書が名指しで禁止している内容だった。

以後、各項目に「根拠: 実測 / 未確認」を明記する。
**未確認の項目は着手前に必ず現物を確認する。**
