# 運用規則の経緯

この文書は事故と実測の記録であり、規則改訂時または同種事故の調査時に読む。毎回の行動は `CLAUDE.md` と `AGENTS.md` に従う。

## Codex の書き込み権限

- 事象: 2026-07-28、`--write` なしで始めた相談の後続で設計書作成が必要になり、読み取り専用のまま7分12秒を失った。同種事故は2回目だった。
- 判明: 権限はジョブ全体に効く。一方、すべての相談へ `--write` を付ける規則は依頼範囲を越える権限になる。
- 今後: 作成・編集を含むジョブは開始時から `--write`、調査・査読だけのジョブは読み取り権限で起動する。

## バックグラウンド実行

- 事象: `--background` だけで起動したため完了通知が届かず、ユーザーの「どうなった？」が唯一の再開契機になった。
- 判明: Codex のバックグラウンド化と、呼び出し側を起こす監視は別の仕組みである。
- 今後: 起動と同時に `job.status` を監視し、`running` 終了時に結果確認へ進む。

## 稼働中の作業ツリー

- 事象: 2026-07-28、Codex が読んでいる対象作業ツリーを Claude Code が3回変更した。うち1回は `simulation.gd` のプローブと Codex の `git diff` が重なった。
- 判明: 読み取り処理でも、途中で内容が変われば測定期間と根拠が汚染される。
- 今後: Codex 稼働中は対象ツリーを固定し、実験と並行作業は別の worktree で行う。

## 成立しなかった契約効果

- 事象: #106 の `CONTRACT-106-012` は、`load()` がパース失敗時にも非 null のスクリプトを返すため、約束した保護効果を持たなかった。判明後も作業を止めずコミットした。
- 判明: 指定されたコード形を実装しても、契約した効果が成立したことにはならない。先在欠陥や課題分離も停止判断を免除しない。
- 今後: 契約効果と実測が食い違った時点で停止し、未達契約を列挙して扱いを相談する。

## 変異検査の差し替え

- 事象: #106 の指定は型推論不能な式だったが、試した式がパースを通ったため、`NotARealType` を使う別種のエラーへ単独で差し替えた。
- 判明: どちらもコンパイルを壊すという類似だけでは、指定された故障を検査した証拠にならない。
- 今後: 指定変異を再現できない場合は停止し、その検査を未検証として相談する。

## 全件実行と変異の単独判定

- 事象: 指定テストの変異検査を全件実行し、「より厳しい」と判断した。実際には別の結合テストが赤くなり、本命の `test_display_scripts_parse` は緑のままだった。
- 判明: 全件の失敗は、狙ったテスト自身が故障を検出した証拠にならない。
- 今後: 変異検査は対象テスト自身の赤を単独で確認し、別テストの失敗と分けて記録する。

## 承認済み判断の扱い

- 事象: 実装不能になった一節を根拠に旧設計書全体を「無効」と宣言し、ユーザーが決めた4政策と一打1回の判断を含む決着済み事項を開け直した。
- 判明: 実装手段の失効は、独立した設計判断の失効を意味しない。記録の書き換え自体も判断を確定させる行為である。
- 今後: 生きている判断と失効した手段を分け、決着済み判断の変更はユーザー承認で確定する。

## 固定値と回帰検査

- 事象: #88b-2 では `state_hash()` を使う検査が動かず、別の乱数列スナップショットが動いた。固定値の一覧だけでは変更の到達先を予測できなかった。
- 判明: 判断基準はテスト名や一覧ではなく、変更原因が各検査の固定対象へ到達するかどうかである。
- 今後: 固定値の変化と不変をどちらも発見として扱い、原因から到達経路を確認する。

## 固定値を再取得するツリー

- 事象: 2026-07-27、壊れた機能と複数理由を含む未コミットツリーで固定値を更新し、新しい値の由来を履歴から追えなくなった。
- 判明: 他の失敗や別理由を含むツリーから得た値は、意図した変更の証拠にならない。
- 今後: 他が緑の分離したツリーで、一つの理由ごとに再取得し、旧値・新値・理由・テスト件数・失敗件数をコミットへ記録する。
