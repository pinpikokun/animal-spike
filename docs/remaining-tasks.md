# 残タスク一覧（優先度付き）

最終更新: 2026-07-25

**この文書の約束**: 作業を終えるたびに、その時点の残タスクを優先度付きでここへ書き直す。
番号は Claude Code のタスク管理の番号と一致させる。完了したものは一覧から消す。

優先度の意味:

| | 意味 |
|---|---|
| P0 | いま手を動かしているもの、および実害のあるバグ |
| P1 | 土台。コードが増えるほど直す手間が増えるので先に片付ける |
| P2 | ゲームの中身。遊んだときの面白さに直結する |
| P3 | 内容物（キャラ・演出・素材） |
| P4 | 製品化・オンライン・整理 |
| P5 | 条件付き・後続 |

**順番の考え方（2026-07-25 改訂）**: ローカルで面白いものを先に作る。
ネット対戦は「不合格ならエンジンを捨てる撤退ゲート」として当初は前倒しされていたが、
既にGodotの上に大量に作ってしまった以上、いま不合格でも撤退は現実的でない。
早くやる価値は薄れたので、ゲームの中身より後ろへ下げた。
ただし土台（乱数方式・キーの設計）だけは、コードが増える前に直す。

## まだタスクに割っていないもの

設計書には書いてあるが、中身が決まっていないためタスクの粒度に落ちていない。
着手時期が近づいたら分解する。

- **M5 製品化**: メニュー・UI・サウンド・Steam統合・生成AIの開示
- **M6 仕上げ**: バランス調整・Steamストアページ・リリース
- オンライン周りの残り: 切断=敗北とロビー帰還、ping常時表示、マッチングのping上限フィルタ、
  設定と戦績のSteamクラウド保存

## 経緯

### この一覧を作った理由（2026-07-25）

ユーザーの指摘で仕様書・原作資料・コード全体を横断で洗い直したところ、
**#82 から #97 までの16件が、文書に書いてあるのにタスクとして追跡されていなかった**
ことが判明した。特に次の3件は影響が大きい。

- **#82 仮想打球テスト** — 原作資料が「CPUの心臓部」「そのまま借りるべき」と書いている中核機構
- **#88 乱数方式** — 業界標準を調べずに選んだ設計
- **#89 キャラ差3軸** — 式だけ通っていて実データが無く、エラーも出ずに全キャラ同一で動いていた

### 優先度を組み直した理由（2026-07-25、同日）

最初の版はネット対戦関連（#25, #72）をP1に置いていた。
根拠は M0 の設計書がネットコード検証を「不合格ならUnityへ移行する撤退ゲート」として
前倒ししていたこと。**しかしこれは Claude Code が古い計画をそのまま引き写したもので、
いまの状況で妥当かを検証していなかった。**

既に Godot の上に大量に作っており、いま不合格でも撤退は現実的でない。
ローカル2プロセスの検証（M2フェーズ1）は合格済みで、方式の見込みはある程度立っている。
つまり「早く確かめる価値」は既に薄れている。

ユーザーの指摘「ゲームがまともに出来上がっていないのにネット対戦を先に詰めるのはおかしい。
ただし乱数のステートフル化のような将来を見据えた設計は先にやるべき」は正しい。
ゲームの中身を P2 へ、ネット対戦を P4 へ移し、土台（#86, #88）だけを P1 に残した。
