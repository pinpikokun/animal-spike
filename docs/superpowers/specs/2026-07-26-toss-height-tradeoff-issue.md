## 0. 前提 (この課題を理解するのに必要な知識)

**対象は「味方へ上げるトス」**。バレーボールで言うレシーブ→**トス**→アタックの2打目にあたる。
上げた球を味方(または自分)がアタックで打つ。

**対象外は「相手コートへ返す球」**。3打目の返球とサーブがこれにあたる。
そちらは別の設計書 `2026-07-26-return-over-net-design.md` で扱っており、
**味方が打たないので、この課題の駆け引きは発生しない。**

本作には次の要素が既にある。この課題はそれらの上に乗る。

| 既にあるもの | 内容 |
|---|---|
| ブロック | 空中で上方向+アクション。相手のアタックを弾き返す |
| ジャスト判定 | リーチの45%以内で打つと威力が上がる。タイミングの上手さを測る仕組み |
| CPUの反応遅延 | 難易度ごとに0.2〜0.4秒。敵が触ってから新しい目標を決めるまでの間 |
| CPU難易度プリセット | 弱/普通/強い/最強。能力ビットと数値で差をつける枠組み |
| トス上手／トス下手 | 付与能力。2026-07-26 に「飛んできた球の勢いに振り回される度合い」で差をつけると決定 |

## 1. 課題 (ユーザー提起、2026-07-26)

> トスって高く上がると人間はアタックしやすいし、2回目のトスもしやすい。
> でもCPUは低いトスでもタイミングよくアタックもトスもできるよね？そこの使い分けが難しいと思っている。
> 普通のバレーでもそうだけど高いトスのほうがアタックも打ちやすいけど、
> 相手にアタックするタイミングがバレバレで防がれやすい。
> 低いトスに速攻のアタックは打つのが難しいけど、
> 相手にアタックするタイミングがばれないのでブロックで防がれづらい。

### 1.1 現実のバレーボールでの構造

トスの高さには、はっきりした損得がある。

| トスの高さ | 攻める側 | 守る側 |
|---|---|---|
| **高い** | 打ちやすい。落下点へ入る時間がある | **タイミングが読めるのでブロックが間に合う** |
| **低い(速攻)** | **打つのが難しい。タイミングの窓が狭い** | 読めないのでブロックが間に合わない |

**「難しいがバレない」と「簡単だがバレる」の交換になっている。** だから使い分けが生まれる。

### 1.2 本作で成立しなくなる理由

この交換は**2つの要素**で成り立っている。

1. **打つのが難しい** = 攻める側が払うコスト
2. **ブロックが間に合わない** = 守る側が受ける不利

**人間が打つときは両方が働く。** 難しいから練習が要る。その代わり通れば強い。

**CPUが打つときは1が消える。** CPUは計算でタイミングを合わせられるので、
低いトスでも難しくない。**2の利点だけが残る。**

**デメリットの無い選択肢は、必ずそればかり使われる。**
放置すると「CPUは常に速攻」という単調な状態になり、駆け引きが死ぬ。

## 2. やってはいけない解き方

**「CPUだけ確率でわざと失敗させる」は採らない。**

理由: 2026-07-25 の実装値監査(`docs/value-provenance-audit.md`)で、
原作には狙いにノイズを注入する処理もわざとミスする処理も**存在しない**ことを確認している。
根拠なく弱くする仕掛けは、遊ぶ側に「なぜ今失敗したのか」が説明できず、不自然に映る。

## 3. 検討したい方向 (2026-07-26 時点の案。決定ではない)

### 案A: 低いトスを「上手さ」として扱い、CPUの難易度で分ける

弱いCPUは低いトスを上げない・打てない。強いCPUだけができる。

- **「強い相手は速攻を使ってくる」**という形になり、CPUが常にできることが
  欠陥ではなく**強さの表現**になる
- 既存の難易度プリセットの枠組みにそのまま乗る
- 人間にとっては、低いトスを使いこなすことが**上達の報酬**になる

### 案B: 低いトスに、CPUにも効くコストを置く

例: 低いトスは触るのが難しく、**トス上手でないと安定しない**。

- キャラの個性で差が出る。CPUも無条件には使えない
- 2026-07-26 に決めた「トス上手／トス下手」の設計と地続き

**案Aと案Bは併用できる。** 現時点ではこの組み合わせが有力と考えている。
