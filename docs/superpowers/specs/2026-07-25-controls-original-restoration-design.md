未完了で、DOCの読み違いを含んでいた。2026-07-25に一次資料を取り直した結果、

| 操作 | 原作 | 設計作成時の実装（2026-07-25） | |
|---|---|---|---|
| 空中・上+ボタン | アタック | ブロック | 乖離 |

## 3. 決定した操作体系

### 3.1 地上 (変更なし)

| 入力 | 動作 |
|---|---|
| 上 | ジャンプ専用。打球の照準には使わない |
| 下+ボタン | レシーブ |
| 後+ボタン | 自陣後方へトス |
| ボタンのみ | 自陣前方へトス |
| 前+ボタン | 敵陣へ打つ。**ただしネット際で相手球が来ていればブロック** |

地上ブロックが新規追加となる。それ以外は2026-07-25時点の実装から変更しない。

### 3.2 空中 (9マス、全面改訂)

| 縦入力 | 後 | なし | 前 |
|---|---|---|---|
| **上** | 通常アタック→敵陣前面 | 通常アタック→敵陣中央 | 通常アタック→敵陣後面 |
| **なし** | 自陣後方へトス | 自陣前方へトス | 敵陣へトス / **ブロック** |
| **下** | ジャスト可アタック→敵陣前面 | ジャスト可アタック→敵陣中央 | ジャスト可アタック→敵陣後面 |

横入力の意味は全行で共通 (後=敵陣前面 / なし=敵陣中央 / 前=敵陣後面)。
トス行だけは着弾ゾーンの意味が変わる (3.4節)。

## 4. 上下の使い分け (本仕様の中心)

**上=通常アタック固定 / 下=タイミングが合えばジャストアタック。**

### 解決する問題

2026-07-25時点の実装では、ジャストアタックは打点の位置だけで決まる
(リーチの45%以内)。
そのため**うまい人ほど意図せずジャストアタックになってしまい、避けられない**。
ジャストアタックはドライブゲージを0.5本消費するので、
「今はゲージを使いたくない」場面が確実に存在するのに、選べない。

### 決定

- 空中で**上**+ボタン: 常に通常アタック。打点が芯でもジャストにならない。
  ゲージ消費0、相手のゲージ削り1本。
- 空中で**下**+ボタン: 打点が芯 (リーチの45%以内) ならジャストアタック。
  外れたら上アタックと完全に同じ結果になる。

つまり**下は「賭ける」入力**であり、上は「賭けない」入力である。
ゲージを使う/使わないの選択権をプレイヤーに戻すのが目的。

### 軌道は上下で変えない

上アタックと下アタックで**着弾位置・速度・角度を変えてはならない**
(ジャスト成立時の速度110%と慣性の違いを除く)。

理由: 軌道まで変えると「ゲージを使うか」と「どこへ打つか」が再び結合し、
本仕様が解こうとしている問題そのものを作り直すことになる。
2026-07-25の設計会でこの案が一度出て、上記の理由により撤回された。
打ち分けは既に左右3方向が担っている。

### 必殺技は下側に乗る

殺人燃えるアタック (空中で下+一定の高さ) など、空中下の必殺技は
**下アタック側にのみ乗る**。上アタックからは必殺技が出ない。
「上=安全な通常攻撃」という性格と一貫する。

## 5. 入力の衝突と解決

「前+ボタン+上下なし」がブロックと敵陣トスで衝突する。**原作も同じ衝突を持つ**。

原作は文脈で解決している (DOC 134行)。同じ条件を採用する:

1. 相手チームが最後に触った球であること (`last_touch_team == 1 - team`)
2. ネット際であること (2026-07-25時点の実装は水平60px以内)

両方を満たすときだけブロック、そうでなければ敵陣トス。
2026-07-25時点の `_is_active_block()` が既にこの2条件を持っているので、
入力条件を「空中の上」から「前」へ差し替えるだけでよい。

この衝突と解決方法はユーザー承認済み。

## 6. 空中トスの自陣狙いと3打目の強制

### 6.1 空中トスを自陣狙いへ戻す

原作の空中トスは自陣を狙う。目標x = `76 - (10 + 26*後)*dir`
(team0 で 66 / 40、ネット中心が76)。敵陣へ送るのは前キーのときだけ。

本作でも空中トスの着弾ゾーンを地上トスと同じ3ゾーンに揃える:

| 横入力 | 着弾 |
|---|---|
| 後 | 自陣後方 |
| なし | 自陣前方 |
| 前 | 敵陣 (ブロック条件を満たさない場合) |

これにより「空中から自陣へつなげない」問題が解消する。
地上と空中で横入力の意味が一致するため、覚えることも減る。

### 6.2 3打目は強制的に敵陣へ

自陣狙いのトスを3打目で出すと、そのまま失点が確定してしまう。
これを避けるため、**そのチームの3打目 (`touches` が上限に達する打撃) は
横入力に関わらず敵陣へ飛ばす**。

ユーザー承認済み。原作に同じ処理があるかは未確認 (7節の未決事項)。

## 7. 波及範囲

### 7.1 CPU (`src/sim/sim_cpu.gd`)

2026-07-25時点のCPUはブロックのために `IN_UP` を出している。これを前方向キーへ
差し替える必要がある。また空中アタック時に `IN_DOWN` を出しているが、
新体系では上下の選択がゲージ戦略になるため、**CPUにも選択基準が要る**。

初版の方針 (シンプルに保つ):

- ドライブゲージに余裕がある (1本以上) → 下 (ジャストを狙う)
- ゲージが不足 / バーンアウト中 → 上 (通常アタック)

難易度プリセットによる出し分けは第2版以降の課題とし、初版では入れない。

### 7.2 表示層 (`src/display/anim_select.gd`)

空中の上+ボタンがブロックからアタックへ変わるため、
ブロック姿勢の出る条件が変わる。ブロックは地上でも出るようになるので、
**地上ブロックの姿勢**が新たに必要になる。原作のセル割当を確認すること
(`docs/reference/original-vb22.md` のスプライトセル対応表)。

### 7.3 ジャンプ高さとの干渉 (2026-07-25 ユーザー判断で許容)

`src/display/input_poll.gd:15` は**上キーで `IN_JUMP` と `IN_UP` を
同時に立てている**。そして `player_movement.gd:196` は上昇中に
`IN_JUMP` が離されるとジャンプを打ち切る (可変ジャンプ)。

したがって現状のままだと:

- 上アタック = 上を押し続ける = `IN_JUMP` 保持 = **ジャンプが最大まで伸びる**
- 下アタック = 上を離して下を押す = `IN_JUMP` が切れる = **ジャンプが低くなる**

### 結論: 許容する。対策を入れない

ユーザー判断 (2026-07-25)。根拠は「設計作成時点でも下+ボタンがアタックであり、
一定の高さを要求する殺人燃えるアタックが実際に問題なく出せている」。
下アタックの到達高さは設計作成時点から変わらないため、**新体系で下側が
不利になるわけではない**。実プレイで既に成立していることを、
机上の推論で先回りして潰す必要はない。

上記の (a) 縦入力を頂点以降のみ有効にする / (b) 保持フラグの分離 /
(c) 可変ジャンプの一時無効化 といった対策は**入れない**。
`IN_JUMP` と `IN_UP` を同時に立てる `input_poll.gd` の実装もそのままでよい。

実装時に注意する点として記録するにとどめる:

- 新たに増えるのは「上アタックの方が高く跳べる」という側であり、
  下アタックが低くなるのではない。上は**ゲージを使わない上に高く跳べる**
  という二重の利点を持つことになる。
- そのため上ばかりが選ばれる可能性はある。ただしジャストアタックは
  速度110%かつ相手のゲージを2本削るので、下側にも明確な見返りがある。
  **どちらが強いかは実プレイで判断する。**事前に数値を動かさない。

## 8. 原作と意図的に異なる点

- ジャストアタック/ジャストレシーブとドライブゲージは原作に存在しない
  本作独自の仕組み。上下の使い分けはその独自要素を操作しやすくするための
  設計であり、原作準拠ではない。原作は上下どちらもただのアタックである。
- 空中トスの着弾ゾーンは原作の実数値 (66 / 40) をそのまま使わず、
  本作の地上トスと同じゾーン定義に揃える。コート寸法が異なるため。

## 9. Verification (実装時にテスト化する要点)

- 空中の上+ボタンがアタックになり、打点が芯でもジャストにならないこと
- 空中の下+ボタンが、芯ならジャスト、外れたら上アタックと同一の結果になること
- 上アタックと下アタック (非ジャスト) の着弾位置・速度・角度が完全に一致すること
- 上アタックからは空中下の必殺技が出ないこと
- ブロックが前キー+ボタンで、空中・地上の両方で成立すること
- ブロックが「相手球 かつ ネット際」の2条件を満たすときだけ成立し、
  条件を外れたら敵陣トスになること
- 空中トスの3ゾーン (後=自陣後方 / なし=自陣前方 / 前=敵陣) が
  team0/team1 で鏡像になること
- 3打目のトスが横入力に関わらず敵陣へ飛ぶこと
- CPUがゲージ残量に応じて上下を出し分けること
- 既存のドライブゲージ消費・削りの数値が変わらないこと
- 下アタックの到達高さが設計作成時点から変わっていないこと
  (7.3節の判断の前提。上が高くなるのは許容するが、下が下がるのは想定外)
