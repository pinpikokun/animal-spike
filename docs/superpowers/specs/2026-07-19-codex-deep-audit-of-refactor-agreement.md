## コードで再確認できた合意点

### _ball_vs_block呼び出しの巻き上げ

`_step_ball` の末尾は `_ball_vs_net`、`_ball_vs_block` の順である。
ブロック呼び出しを次の3つの字句上の位置へ移せば順序を保てる。

1. サーブ中の `_step_ball` 直後
2. ラリー中の `_step_ball` 直後
3. `_step_ball_loose` 内部の `_step_ball` 直後

point-pauseとgame-overは3を共有するため、実行経路は4つだが編集位置は3つである。
3ではphase guardによりブロックがno-opになる。呼び出し自体を残す案に同意する。

巻き上げ後、`_step_ball` の `inputs` 引数は未使用になる。逐語抽出コミットでは
引数を残す。削除するなら、抽出後の独立した機械変更にしてハッシュ不変を確認する。

### ball_physicsの境界

初回は `_step_ball`、`_step_ball_loose`、`_ball_vs_net` と、それらだけが使う
球単体定数を移す。`_ball_vs_block` は移さない。`cfg.net_top_original` は後で
廃止予定だが、挙動不変抽出中には条件も参照も変更しない。

### player_movementの境界

`_step_player` はFP、Chars、SimInputと移動系定数で閉じられるため、葉として
抽出できる。ただし対象は通常移動とジャンプだけではない。ダッシュ、スキッド、
ヒップアタック、壁張り付き、throw中の移動停止も同じ関数に含まれる。
工程4の合格条件には `test_dash.gd`、`test_skid.gd`、`test_hip_cling.gd`、
`test_hat.gd` も明記する。

`test_char_stats.gd` の `Sim._jump_height_px` 直接参照は、工程4と同じコミットで
新しい所有先へ更新してよい。

### 特性テストと同期

既存238テストは壁、ネット、ブロック、push、帽子、ダッシュ、スキッド、
ヒップ、壁張り付きの個別経路を広く持つ。一方、60秒CPUゴールデンがそれらを
必ず通る保証はない。狙ったヒット連鎖を通す第2ゴールデン追加は必要である。

## 未解決1: PUSH定数の所有

前回答を維持する。

- `PUSH_UNIT_PX` / `PUSH_DECAY` は `player_movement.gd` が所有する。
- `PUSH_ATK_TICKS` / `PUSH_BLK_TICKS` / `PUSH_STUN_TICKS` /
  `PUSH_MAX_TICKS` は `hit_resolver.gd` が所有する。

工程4では前者だけを移す。後者はsimulationに残し、工程5でヒット処理と一緒に
移す。定数の重複も循環も発生しない。移動モジュールにアタック、ブロック、
ガードブレイクのルールを所有させる技術的理由はない。

## 未解決2: 帽子定数ミラー解消の行き先

Claude Code案は工程6でsim_cpuの帽子ミラー定数を正式参照へ置換するとしているが、
工程5の `hit_resolver.gd` は帽子の所有者ではない。帽子の生成、飛行、滞在、帰還、
ボール衝突は `_update_hat` にあり、ヒット解決抽出後もsimulation側に残る。
したがって `sim_cpu -> hit_resolver` ではミラーを解消できない。

実利用も再確認した。sim_cpuで現在使われるミラーは次だけである。

- `HAT_KIND`
- `HAT_GUARD_COST`
- `HAT_FLY_PX`
- `HAT_OUT_TICKS`

`HAT_WINDUP`、`HAT_HOVER_TICKS`、`HAT_RADIUS_PX`、`HAT_HAND_UP_PX` は
guardian test以外では使われていない。

選択肢は二つある。

1. 推奨: 工程6を今回のリファクタリングから外す。帽子は固有技であり、今回の
   能力・トス仕様では変更しない。guardian testを残し、将来の固有技整理で
   `_update_hat` と共有定数を同時に設計する。
2. 今回解消するなら、`hat_rules.gd` のような葉を新設し、simulationとsim_cpuの
   双方が参照する。ただしこれは当初の3責務限定を広げるため、別設計・別承認が必要。

YAGNIと今回の範囲を優先し、選択肢1を採用するよう求める。
