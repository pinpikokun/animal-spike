# 原作地上必殺技許可ゲート設計

## 1. 目的

CPUが地上必殺技を候補にできるかを、原作「VOLLEY BALL 2on2」の難易度別許可ゲートへ合わせる。

これは必殺技の実使用率を固定する仕様ではない。許可後も接触、ゲージ、キャラクター、入力、技固有条件を満たした場合だけ必殺技が成立する。

## 2. 根拠

- 原作解析の正本: `docs/reference/original-vb22-cpu-ai.md` 200-208行
- 過去の採用決定: `docs/tasks/84.md` 20-40行
- 状態乱数の実装: `src/sim/sim_rng.gd` と `src/sim/simulation.gd`
- CPUプロファイルの正本: 新設する `src/sim/cpu_profile.gd`
- 原作キャラ必殺技の正式仕様: `docs/superpowers/specs/2026-08-02-original-character-special-moves-design.md`

原作解析では、地上必殺技の許可に `aitick` と `RND` を難易度ごとに使い分ける。2026-07-27のユーザー決定により、率だけでなく変数の使い分けも移植対象である。

## 3. 現在の問題

現行の `_wants_special()` は地上必殺技と空中必殺技を同じ判定へ通す。

現行プリセットでは次の結果になる。

| 難易度 | 現行の地上必殺技許可 |
|---|---:|
| イージー | 0% |
| ノーマル | 0% |
| ハード | 153/256、約59.8% |
| スーパー | 常時 |

イージーとノーマルは能力フラグで拒否されるため、確率値だけを差し替えても原作率にならない。

## 4. 設計原則

必殺技の種類は、既存カタログの `activation.contact` を正本にする。

| 接触種別 | 用途 | CPU許可方針 |
|---|---|---|
| `SPECIAL_CONTACT_GROUND_HIT` | 地上接触で成立する打球必殺 | 今回の原作ゲート |
| `SPECIAL_CONTACT_AIR_HIT` | 空中接触で成立する打球必殺 | 現行プロファイル判定 |
| `SPECIAL_CONTACT_AIR_ACTION` | DUOの吸い込み | 現行プロファイル判定 |
| `SPECIAL_CONTACT_BLOCK` | SEC1の亜空間ブロック | 現行のブロック判断 |
| `SPECIAL_CONTACT_AUTO_AIR_ATTACK` | 自動派生する空中攻撃 | CPU入力ゲート対象外 |

同じ必殺技IDが地上と空中の両方に発火条件を持つ場合も、現在選ばれている接触種別で方針を決める。技ID、キャラクターID、地上で発動できるかの個別列挙は追加しない。

CPUの使用方針と必殺技の合法性は分離する。

- CPU使用方針は「その候補を要求するか」だけを決める。
- `SpecialMoves` は人間とCPUに共通の入力、接触、費用、技固有条件を決める。
- 使用方針は球、プレイヤー、ゲージを変更しない。

## 5. 適用範囲

変更対象はCPUの地上必殺技候補だけとする。

対象:

- 原作8キャラクターが持つ `SPECIAL_CONTACT_GROUND_HIT` の入力候補
- CPU難易度4段階の許可ゲート
- 許可判定を検証する単体テストとCPU入力テスト

対象外:

- 空中必殺技
- DUOの吸い込み
- SEC1の亜空間ブロック
- 人間操作
- 必殺技の発動条件、効果、消費量
- CPUの位置取り、接触判断、通常攻撃判断
- 味方CPUと敵CPUへ割り当てる難易度そのもの

対象外の必殺技は現行のプロファイル判定または専用判断を維持する。

## 6. CPUプロファイルの方針値

地上必殺技ゲートを `P_TIQ` から推測しない。`P_TIQ` は配球知能であり、難易度や必殺技方針の識別子ではない。

パック済みCPUプロファイルを `src/sim/cpu_profile.gd` へ分離し、`P_GROUND_SPECIAL_POLICY_SHIFT = 56` と `GROUND_SPECIAL_POLICY_MASK = 0x7` を追加する。地上必殺技の許可方式を3bitで明示的に持たせる。

既存フィールドは `P_TIQ = 48` の8bit、つまりbit 48から55までを使う。新フィールドはbit 56から58だけを使い、bit 59から62は未使用、bit 63の符号bitには触れない。読み出しは必ず次の式を使う。

```gdscript
(profile >> P_GROUND_SPECIAL_POLICY_SHIFT) & GROUND_SPECIAL_POLICY_MASK
```

| 方針値 | 意味 |
|---:|---|
| 0 | 現行プロファイル判定を維持 |
| 1 | 原作イージー |
| 2 | 原作ノーマル |
| 3 | 原作ハード |
| 4 | 原作スーパー |

4つの本番プリセットはそれぞれ1から4を設定する。`make_profile()` の既定値は0とし、テストや独自プロファイルの既存挙動を暗黙に変えない。未定義値5から7は不許可にし、現行判定へ黙って戻さない。

この方針値は難易度の代理ではなく、CPUプロファイルが持つ一つの行動方針である。将来、キャラクター調整で他のプロファイル値を変えても地上必殺技方針は維持される。

## 7. 許可ゲート

地上必殺技の許可条件は次のとおりとする。

| 難易度 | 許可条件 | 剰余上の比率 |
|---|---|---:|
| イージー | `s.aitick % 8 == 0` | 1/8、12.5% |
| ノーマル | `s.rng % 4 == 0` | 1/4、25% |
| ハード | `s.aitick % 3 < 2` | 2/3、約66.7% |
| スーパー | `s.rng % 4 < 3` | 3/4、75% |

この比率は値の剰余に対する許可率であり、試合中の必殺技実使用率ではない。

## 8. 乱数と状態の契約

- `aitick` は打球時に更新され、同じ打球の間は固定される。
- `rng` は `Simulation.tick()` の先頭で毎フレーム1回更新される。
- 許可ゲートは現在値を読み取るだけで、`rng` と `aitick` を進めない。
- イージーとハードは同じ打球中に許可結果が変わらない。
- ノーマルとスーパーはフレーム更新された `rng` に応じて許可結果が変わり得る。
- actor番号、技ID、派生ハッシュ、`SALT_SUPER` は原作地上許可ゲートへ混ぜない。
- ロールバックと同期ハッシュの既存契約を変えない。

## 9. 入力決定の順序

地上接触時は次の順序で処理する。

1. 原作8キャラクターか確認する。
2. 守備の緊急接触ではないことを確認する。
3. `SpecialMoves.hit_contact_for_player()` で現在の打球接触種別を得る。
4. 接触種別に対応するCPU使用方針を確認する。
5. 許可された場合だけ、既存順序で必殺技の入力候補を走査する。
6. `SpecialMoves.select_hit_special()` が合法と判定した最初の入力を返す。
7. 候補がない場合は通常接触判断へ戻る。

地上接触種別だけ原作ゲートを使う。空中接触種別は現行プロファイル判定と既存候補順序を維持する。

DUOの吸い込みは `select_hit_special()` を通らない独立行動であり、`can_start_action()` の専用経路と現行プロファイル判定を維持する。SEC1の亜空間ブロックも `_decide_block()` と `can_request_block_enhancement()` の専用経路を維持する。

## 10. API設計

`src/sim/special_moves.gd` に、既存の接触分類を一か所へ集約する純粋関数を追加する。

```gdscript
static func hit_contact_for_player(p) -> int
```

この関数は `p.on_ground == 1` なら `SPECIAL_CONTACT_GROUND_HIT`、`p.on_ground == 0` なら `SPECIAL_CONTACT_AIR_HIT`、それ以外なら `-1` を返す。乱数、球、内部フレーム状態を読まず、副作用を持たない。`select_hit_special()` とCPU方針選択は同じ関数を同じCPU判断中に使い、分類の重複をなくす。

`src/sim/cpu_profile.gd` を新設し、次をCPUプロファイルの正本として移す。

- `AB_*` 能力フラグ
- `P_*` シフト値
- 4つの `PRESET_*` と `PRESETS`
- `make_profile()` と `prof_byte()`
- 地上必殺方針の3bit定義

`src/sim/sim_cpu.gd` は互換APIとして `CpuProfile` の定数と関数を別名参照する。既存の呼び出し側を一斉変更せず、定義値の正本だけを分離する。

`src/sim/sim_state.gd` は `CpuProfile.PRESET_MAX` をプレイヤーCPUの既定値に使う。巨大なプロファイル整数を複製しない。

地上必殺方針として次を追加する。

- `P_GROUND_SPECIAL_POLICY_SHIFT = 56`
- `GROUND_SPECIAL_POLICY_MASK = 0x7`
- 現行、原作イージー、原作ノーマル、原作ハード、原作スーパーの方針値
- `CpuProfile.make_profile()` の末尾に既定値付き方針引数

`src/sim/sim_cpu.gd` に次の純粋関数を置く。

```gdscript
static func _profile_special_allowed(s, idx: int, prof: int) -> bool
static func _ground_hit_special_allowed(s, idx: int, prof: int) -> bool
static func _hit_special_allowed(s, idx: int, prof: int, contact: int) -> bool
```

`_profile_special_allowed()` は現行 `_wants_special()` の改名であり、挙動を変えない。

`_ground_hit_special_allowed()` は3bitの方針値を読み、方針1から4では原作ゲート、0では `_profile_special_allowed()`、5から7では不許可を返す。

`_hit_special_allowed()` は接触種別に応じて次を使い分ける。

- `SPECIAL_CONTACT_GROUND_HIT`: `_ground_hit_special_allowed()`
- `SPECIAL_CONTACT_AIR_HIT`: `_profile_special_allowed()`
- その他: 不許可

DUO吸い込みと `_should_use_flame()` は `_profile_special_allowed()` を使い、意味を変えない。亜空間ブロックはこれらの関数を通さない。

## 11. 不変条件

- 人間とCPUは必殺技の合法性、費用、成立結果を引き続き共有する。
- CPUの許可判定だけで球、プレイヤー、ゲージ、乱数状態を変更しない。
- 原作8キャラクター以外へ必殺技入力を追加しない。
- 相手の攻撃に対する守備接触を必殺技へ置き換えない。
- 空中打球必殺、吸い込み、強化ブロックの判断結果を変えない。
- 地上必殺技が不許可または不成立なら、通常接触へフォールバックする。
- CPUプロファイルのビット割当、プリセット、既定値を複数ファイルへ数値で複製しない。

## 12. 検証

単体テストでは、手計算した剰余を使い次を確認する。

- イージーは `aitick` の0から7で1件だけ許可する。
- ノーマルは `rng` の0から3で1件だけ許可する。
- ハードは `aitick` の0から2で2件許可する。
- スーパーは `rng` の0から3で3件許可する。
- `aitick` を使う難易度は `rng` を変えても結果が変わらない。
- `rng` を使う難易度は `aitick` を変えても結果が変わらない。
- 全判定で `rng` と `aitick` が変化しない。
- 本番4プリセットが原作方針1から4を保持する。
- 3bit以外の既存プロファイルbitとbit 63を変更しない。
- `make_profile()` の既定値0は現行プロファイル判定へ戻る。
- 未定義方針5から7は不許可になる。
- `SimState.Player.cpu` の既定値が `CpuProfile.PRESET_MAX` と同じ正本を参照する。

CPU入力テストでは次を確認する。

- 地上で許可されたときだけ合法な必殺技入力を返す。
- 地上で拒否されたときは必殺技入力を返さない。
- 地上と空中の両方を持つ同一必殺技IDでも、接触種別ごとの方針を使う。
- HITOの消える球、PIYOの突風球、UMEのふらふら攻撃は地上発火だけ原作ゲート、空中発火は現行判定を使う。
- 空中入力は既存プロファイル判定の許可結果を維持する。
- DUO吸い込みは現行プロファイル判定を維持する。
- SEC1強化ブロックは専用判断を維持する。
- `hit_contact_for_player()` と `select_hit_special()` は地上、空中、不正な `on_ground` で同じ分類契約を使う。
- ゲージ不足とバーンアウトでは、許可されても必殺技入力を返さない。

変更後に対象テストを実行し、最後に正規入口 `run_tests.ps1` で全件検証する。

## 13. 合格条件

1. 地上必殺技の4難易度が原作の剰余条件と一致する。
2. `aitick` と `rng` の使い分けが原作解析表と一致する。
3. 許可判定が状態を変更しない。
4. イージーとノーマルも原作条件を満たせば地上必殺技候補を出せる。
5. 空中打球必殺、吸い込み、強化ブロックの現行判断を変えない。
6. 必殺技の合法性、費用、効果を変えない。
7. 方針フィールドがbit 56から58だけを使用する。
8. 不正な方針値と接触状態を無音で別方針へ丸めない。
9. CPUプロファイルの巨大な既定値リテラルを `SimState` に残さない。
10. 対象テストと全件テストが成功する。

## 14. 停止条件

次を検出した場合は実装を停止して報告する。

- 原作解析表と異なる剰余条件が必要になる。
- 既存カタログの接触種別だけでは方針を一意に選べない。
- プロファイルの追加方針値が同期状態へ収まらない。
- 同期ゴールデン以外の固定値、配列、ハッシュが意図せず変わる。
- 正規入口の全件テストを実行できない。
