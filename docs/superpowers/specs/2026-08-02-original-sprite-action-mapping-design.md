# 原作8キャラのスプライト動作対応を完成させる設計

Status: ユーザー指摘反映版。実装前レビュー待ち。

## 1. 目的

原作8キャラの24セルを、本来の動作名と再生規則へ対応させる。
正本は `00_sprite-sample/スプライトセル対応表.txt` とする。
根拠の追加調査は打ち切り、表に明記された内容を実装契約として扱う。

対象キャラはトメ、ヒト、ピヨ、ウメ、カービィ、デュオ、隠し1、隠し2の8体。
既存のオリジナルキャラや参考キャラの素材は変更しない。

## 2. 採用方式

### A. 全セルを今登録し、未実装のゲーム状態は後から接続する（採用）

感電、泡、飛行、特殊落下を含む全セルを正しく登録し、セル番号と再生規則を
自動テストで固定する。現在ゲーム状態が存在しない動作も除外しない。
将来その状態を実装したとき、登録済みのアニメ名を選べば正しい絵が出る形にする。

### B. 現在到達できる動作だけ登録する（不採用）

変更量は少ないが、将来実装する動作の素材契約が再び曖昧になる。

### C. 感電や泡などのゲーム挙動も今回実装する（不採用）

スプライト対応から物理、必殺技、状態遷移へ範囲が広がる。
今回は表示資産と再生契約を完成させ、ゲーム挙動の追加は各機能の設計で行う。

| `jump` | 2 | 上昇姿勢 |
| `attack` | 3, 4, 5 | 2tickずつ。3、4、5の後は4と5を交互 |
| `receive_stance` | 6 | レシーブ構え |
| `toss` | 7 | 真上へ打ち上げるトス |
| `ground_swing` | 9, 8, 7, 6 | 2tickずつ進み、最後の6を硬直終了まで保持 |
| 原作8キャラの`toss_fwd` | 9, 8, 7, 6 | 敵陣へ返す地上打撃。再生は`ground_swing`と同じ |
| `dive` | 11, 10, 7, 0 | 2tickずつ |
| `hurt` | 12 | 強打被弾 |
| `shock` | 12, 13 | 3tickずつ交互 |
| `stun` | 14, 15 | 3tickずつ交互 |
| `burn` | 16, 17 | 3tickずつ交互 |

## 4. 実装済みアクションとの接続

ブロック、トス、アタック、レシーブ、横っ飛びはすでにゲームへ実装されている。
今回、それぞれを次の原作セルへ直結する。

| ゲーム中の動作 | 表示する原作セル |
|---|---:|
| 地上・空中ブロック成功 | 9 |
| 地上・空中トス | 7 |
| 空中アタック | 3、4、5。その後4、5交互 |
| 下+ACTIONのレシーブ構え | 6 |
| 地上レシーブの実打 | 9、8、7、6 |
| 敵陣へ返す地上打撃 | 9、8、7、6 |
| 横っ飛びレシーブ | 11、10、7、0 |

現行の `hit_kind` はブロック、レシーブ、トス、前方打撃を表現できるが、
実際に記録されるのはブロック、レシーブ、トスだけで、前方打撃は死んでいる。
空中アタックを表す値もなく、空中打球時は直前の値が残留する。
その結果、空中トスがアタック絵になり、直前がブロックなら次の空中トスや
空中アタックまでブロック絵になる場合がある。

表示のための空中アタック種別を追加し、打球成立時に次を必ず記録する。

- 地上レシーブ: `RECEIVE`
- 自陣へ上げる地上・空中トス: `TOSS`
- 敵陣へ返す地上・空中トス: `FORWARD`
- 空中アタック: `ATTACK`
- 地上・空中ブロック: `BLOCK`

表示側は接地中の `FORWARD` を前方地上打撃、空中の `FORWARD` をトスとして扱う。
原作8キャラの前方地上打撃には9、8、7、6を登録し、既存キャラの専用
`toss_fwd` 素材はそのまま使う。物理結果は変えない。

`ground_swing` と原作8キャラの `toss_fwd` は、`hit_cooldown` の経過から
9、8、7、6を2tickずつ選ぶ。セル6へ到達後は硬直終了までセル6を保持する。
空中アタックも同じ方法で3、4、5を2tickずつ表示し、その後は4、5を2tickずつ交互にする。

飛行時のセル18固定は、通常の羽ばたきとは別に `fly_hover` として登録する。
現行には原作キャラの飛行操作がないため、ゲーム状態への接続だけは飛行実装時に行う。
感電、泡、特殊落下も同様に、アニメ資産は今回完成させ、対応する状態の実装時に接続する。

## 5. 実装範囲

- `sprite_factory.gd`
  - 原作8キャラの全アニメについてセル番号、順番、保持tickを表へ合わせる。
  - ピヨの泡だけセル4へ分ける。
  - 飛行中の静止姿勢 `fly_hover` にセル18を登録する。
  - 未実装状態のアニメも削除せず登録する。
- `anim_select.gd` / `game_view.gd`
  - 実装済みのブロック、トス、アタック、レシーブ、横っ飛びを上表へ合わせる。
  - アタック、気絶、炎上、勝利の再生規則を表へ合わせる。
  - `ground_swing` と空中アタックのコマを `hit_cooldown` から決め、
    ロールバック後も同じ状態なら同じコマを表示する。
  - 炎上の直接選択に使う `state.tick / 4` も3tick周期へ変更する。
  - 感電、泡、飛行、特殊落下の仮状態や仮分岐は作らない。
- `sim_state.gd` / `hit_resolver.gd`
  - 空中アタック種別を追加する。既存の直列化配列へ新フィールドは追加しない。
  - 地上トス、前方打撃、空中トス、空中アタック、ブロック、レシーブの成立時に、
    対応する `hit_kind` を必ず記録する。
  - 変更するのは表示が読む動作種別だけで、打球物理と入力条件は変更しない。
- テスト
  - 原作8キャラ全員について全アニメのセル領域、順番、保持tickを検査する。
  - ピヨだけ泡セル4、他7体はセル20であることを検査する。
  - 実装済みの各動作が上表のアニメ名を選ぶことを検査する。
  - 空中トスがアタック絵にならず、空中アタックがトス絵にならないことを検査する。
  - 直前のブロック種別が残った状態から空中トス・空中アタックを成立させても、
    ブロック絵にならないことを検査する。
  - アタック終端が4と5を交互に選ぶことを純粋関数で検査する。
  - 既存のブロック、横っ飛び、勝利、炎上表示を壊していないことを検査する。

## 6. 不変条件

- simの物理、入力、当たり判定、ゲージ、乱数は変更しない。
- `hit_kind` は既存の直列化対象なので同期状態の形式は変更せず、記録される値だけを正す。
- 表示コマの時間単位は本作の1 simulation tickとする。対応表のtickを追加換算しない。
- 原作8キャラ以外の画像ファイルとセル割り当ては変更しない。
- キャラクター選択数と選択手順は変更しない。
- 承認済みの地上トス、レシーブ、ブロック、横っ飛びの操作結果は変更しない。
- 感電、泡、飛行、特殊落下のゲーム挙動は今回作らないが、素材登録は完成させる。

## 7. 検証と合格条件

1. 新しいセル契約テストを先に追加し、現行の保持tickとピヨの泡で失敗することを確認する。
2. 最小実装後に同じテストが合格することを確認する。
3. `run_tests.ps1` を正規入口として全件実行し、失敗0、SCRIPT ERROR 0を確認する。
4. `hit_kind` の正しい記録によって固定ハッシュが変化した場合は停止し、旧値と実測値を報告する。
   `hit_kind` 以外の状態値が変化していた場合は契約違反として実装を戻す。
5. Claude Codeへ変更差分とテストをレビュー依頼し、指摘をコードと契約に照合する。
6. 自動検証後、ユーザーが原作8キャラでアタック、レシーブ、横っ飛び、被弾、
   気絶、炎上、勝利を試遊できる状態にする。
