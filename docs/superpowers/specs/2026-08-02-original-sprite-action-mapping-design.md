# 原作8キャラのスプライト動作対応を完成させる設計

Status: ユーザー指摘反映版。実装前レビュー待ち。

## 1. 目的

原作8キャラの24セルを、本来の動作名と再生規則へ対応させる。
正本は `00_sprite-sample/スプライトセル対応表.txt` とする。
根拠の追加調査は打ち切り、表に明記された内容を実装契約として扱う。

対象キャラはトメ、ヒト、ピヨ、ウメ、カービィ、デュオ、隠し1、隠し2の8体。
既存のオリジナルキャラや参考キャラの素材は変更しない。

## 2. 採用方式

### A. 全セルを今登録し、未実装のゲーム状態は後から接続する（採用）

感電、泡、飛行、特殊落下を含む全セルを正しく登録し、セル番号と再生規則を
自動テストで固定する。現在ゲーム状態が存在しない動作も除外しない。
将来その状態を実装したとき、登録済みのアニメ名を選べば正しい絵が出る形にする。

### B. 現在到達できる動作だけ登録する（不採用）

変更量は少ないが、将来実装する動作の素材契約が再び曖昧になる。

### C. 感電や泡などのゲーム挙動も今回実装する（不採用）

スプライト対応から物理、必殺技、状態遷移へ範囲が広がる。
今回は表示資産と再生契約を完成させ、ゲーム挙動の追加は各機能の設計で行う。

## 3. セル対応契約

| アニメ名 | セル | 再生契約 |
|---|---:|---|
| `idle` / `run` | 0, 1 | 立ちと歩きで共用 |
| `jump` | 2 | 上昇姿勢 |
| `attack` | 3, 4, 5 | 2tickずつ。3、4、5の後は4と5を交互 |
| `receive_stance` | 6 | レシーブ構え |
| `toss` | 7 | 真上へ打ち上げるトス |
| `ground_swing` | 8, 9 | 地上打撃スイング |
| `dive` | 11, 10, 7, 0 | 2tickずつ |
| `hurt` | 12 | 強打被弾 |
| `shock` | 12, 13 | 3tickずつ交互 |
| `stun` | 14, 15 | 3tickずつ交互 |
| `burn` | 16, 17 | 3tickずつ交互 |
| `fly` | 18, 19, 20, 19 | 3tickずつピンポン |
| `bubble` | 20 | ピヨだけセル4を代用する |
| `victory` | 21, 22 | 毎tick交互 |
| `fall_special` | 23 | 特殊落下 |

`block` は後日の一次解析と承認済みタスク#70によりセル9を使う。
対応表作成後に確定した契約なので維持する。

セル8から7、6へ戻る遷移と、飛行時のセル18固定は、対応表に存在するが
現在の状態だけでは発火条件を区別できない。必要なゲーム状態を実装する際に接続する。
セルとアニメ資産は今回の検査対象に含める。

## 4. 実装範囲

- `sprite_factory.gd`
  - 原作8キャラの全アニメについてセル番号、順番、保持tickを表へ合わせる。
  - ピヨの泡だけセル4へ分ける。
  - 未実装状態のアニメも削除せず登録する。
- `anim_select.gd` / `game_view.gd`
  - 現在到達できるアタック、気絶、炎上、勝利の再生規則を表へ合わせる。
  - 感電、泡、飛行、特殊落下の仮状態や仮分岐は作らない。
- テスト
  - 原作8キャラ全員について全アニメのセル領域、順番、保持tickを検査する。
  - ピヨだけ泡セル4、他7体はセル20であることを検査する。
  - アタック終端が4と5を交互に選ぶことを純粋関数で検査する。
  - 既存のブロック、横っ飛び、勝利、炎上表示を壊していないことを検査する。

## 5. 不変条件

- simの物理、入力、当たり判定、ゲージ、乱数、同期状態は変更しない。
- 原作8キャラ以外の画像ファイルとセル割り当ては変更しない。
- キャラクター選択数と選択手順は変更しない。
- 承認済みの地上トス、レシーブ、ブロック、横っ飛びの操作結果は変更しない。
- 感電、泡、飛行、特殊落下のゲーム挙動は今回作らないが、素材登録は完成させる。

## 6. 検証と合格条件

1. 新しいセル契約テストを先に追加し、現行の保持tickとピヨの泡で失敗することを確認する。
2. 最小実装後に同じテストが合格することを確認する。
3. `run_tests.ps1` を正規入口として全件実行し、失敗0、SCRIPT ERROR 0を確認する。
4. 固定ハッシュが変化した場合は表示だけの変更という前提に反するため停止する。
5. Claude Codeへ変更差分とテストをレビュー依頼し、指摘をコードと契約に照合する。
6. 自動検証後、ユーザーが原作8キャラでアタック、レシーブ、横っ飛び、被弾、
   気絶、炎上、勝利を試遊できる状態にする。
