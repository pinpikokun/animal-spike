# 原作「VOLLEY BALL 2on2」実機プレイ観察 (2026-07-11)

ユーザーがNeko Project 21/W(PC-98エミュ)で原作を実機プレイし記録した観察。
Animal Spikeの「本物の手触り」を作るための一次資料。スクショ3枚付き(会話ログ参照)。

## 決定事項: コートは左右1軸(奥行きは描画演出)

ユーザー確認済み: **キャラは左右(ネットに近い/遠い)だけ動く。奥・手前(奥行き方向)には動かない。**
画面の「斜め」「手前と奥」はオブリーク投影の見た目であり、ゲームロジックは1軸。
=> 現行の1次元sim(src/sim/)の骨格は正しい。z軸追加のような大改修は不要。
M3は「1軸simへの機能追加 + 表示層の描画磨き」となる。

## 14観察(原文の要点)と対応方針

1. ネットもステージも微妙に斜め => 表示: オブリーク投影(描画層のみ、rollback影響ゼロ)
2. キャラが微妙に手前と奥にいる => 表示: 相方を少し上/下にずらして奥行き感(ゲームは1軸)
3. ネット高さはキャラよりちょっと高いくらい => 寸法: ネットを下げる
4. ジャンプ=↑ボタン、レシーブ=スペース(原作の操作) => 現行(Z/Space=跳,X=技,C=交代)は変更しない方針
5. サーブはコート線の後ろから。打つまで足はバタバタできるが動けない => M3: サーブ位置ロック+足踏みアニメ
6. 方向ボタン+レシーブでボールが近いと前方/後方へ飛び込みレシーブ => M3: 方向ダイブレシーブ(方向にリーチ拡張)
7. レシーブ時は小さくジャンプする => M3/演出: レシーブ小ホップ
8. レシーブした玉の高さ・ジャンプ力がけた違いに高い => 寸法/M3: bump_up大幅増
9. ネットに当たった時ちゃんと跳ねる => 実装済(test_ball_bounces_off_net_below_top)。一致
10. 素レシーブは少し前、横を押してレシーブすると遠くへ飛ぶ => M3: 横入力でレシーブ飛距離/方向を変える
11. 玉は普段ゆったり。アタック時は弾が潰れて速い => 寸法/演出: 浮遊感+スパイク速度+スカッシュ演出
12. 自分が前に行くと相方(CPU)は後ろへ、後ろに行くと相方は前へ => M3: 相補ポジショニング(左右軸で担当ゾーン分担)
13. ただし玉が飛んで来たら相方も近づくので、二人とも前/後になることもある => M3: 相補を既定にしつつボール追いで上書き
14. カエルの技=メテオアタック(隕石級の威力)。コマンドではなくアタックをボールにジャストのタイミングで当てると発動。アタック判定は甘めで少しズレても打てる。タイミングで玉の威力やスタン値が上がってよい => M3: タイミング判定→ヒット品質(威力/スタン)。必殺の芯となる仕組み

## 追加観察(第2次、2026-07-11)

15. レシーブに入射ボールの慣性が乗る。素レシーブは少し前へ飛ぶが、相手の強いアタックをレシーブすると勢いに負けて真上に飛ぶこともある => ヒットは固定速度セットではなく入射速度を反映(反射+吸収)する物理へ。M3aヒットモデルの芯
16. 自分でトスして自分でアタックできる(セルフトス→セルフアタック) => 同一プレイヤーが連続ヒット可(cooldown/max_touches内)。現行モデルで概ね可能か要確認
17. 歩き/トス(小ジャンプ)/トス(横飛び込み)/ジャンプ/アタック等、多彩なアクションがぐりぐり動く => アニメ状態の拡充(表示+アニメ選択)。本番キャラは多フレーム前提(M3b)
18. サーブ時はボールとキャラが重なる(高く浮かせて保持ではない) => serve保持位置をキャラ重なりに
19. サーブはプレイヤー主導。自分でトスボタン→ボールが真上へ→そのままジャンプでアタック=アタックサーブ、または前+トスで緩いサーブ => サーブ=セルフトス+セルフヒット。点5(線の後ろ・打つまで動けない)と統合
20. 原作のボールはしっかりバレーボール(滑らか)。我々のボールはガビガビでバレーボールに見えない => 表示/素材: 適正サイズのドット絵バレーボールに差し替え(144pxの過剰縮小が原因の可能性)。「美しい」基準に不合格、要改善
21. ボールとキャラの比率は原作の方がボールが大きい(点3・寸法を補強)

### ヒットモデルの核心(synthesis)

原作のトス/レシーブ/スパイク/サーブは全て「ヒット」で、結果 = 入射ボール速度(慣性) + プレイヤー状態(接地/空中) + 方向入力 で決まる。
- 素ヒット=少し前、方向入力で飛距離/方向が変わる、強い入射をレシーブすると真上に浮く(慣性に負ける)
- サーブ = セルフトス(真上へ) + セルフヒット。ジャンプ+アタック=アタックサーブ、前+トス=緩いサーブ
- 現行の固定速度セット(_apply_hit)を「慣性反映型ヒットモデル」へ発展させるのがM3aの心臓部

## M3の分解

- **M3a(機能・今すぐ着手可)**:
  - 中核: **慣性反映型ヒットモデル**(15,10,8)=入射速度+状態+方向入力で結果が決まる
  - **プレイヤー主導サーブ**(5,18,19)=線の後ろで位置ロック、セルフトス→ジャンプ+アタック(アタックサーブ)or前+トス(緩いサーブ)、ボールはキャラ重なり
  - 方向ダイブレシーブ(6)、レシーブ小ホップ(7)、セルフトス→セルフアタックの担保(16)
  - CPU相補ポジショニング(12,13)、タイミング判定→威力/スタン(14)
  - 寸法調整(3,8,11,21)、**ボール素材の差し替え**(20=ガビガビ解消・適正サイズのドット絵バレーボール)
  - アニメ状態の拡充(17)=歩/トス小ジャンプ/横飛び込み/ジャンプ/アタック/サーブ足踏み
  - 1軸simへの機能追加+描画磨き。feel値は実物でユーザーが判定(気持ちよさの掟)。
- **M3b(内容・共同設計会が前提)**: キャラ8体前後の確定、各キャラの必殺サーブ/スパイク、ゲージ制の詳細。

## 表示の斜め(オブリーク投影)について

点1・2はすべて表示層(src/display/view_transform.gd等)の話で、決定論sim・ロールバックには一切影響しない。
1軸のsim座標(x=左右, y=高さ)を、少し傾いた投影+相方の奥行きオフセットで描けば原作の見た目に寄る。
CRT/スキャンライン同様「表示だけ」なのでM2ゲートの前提を崩さない。
