# 実装値の根拠監査

作成: 2026-07-25。タスク #99。

**目的**: ゲームの挙動を決める数値のうち、根拠のないものを洗い出す。

**きっかけ**: 同日、Claude Code が根拠のない数値を実装へ入れた事例が3件発覚した
(CPUの狙い誤差・ミス抽選の方針、役割入替の180コマ、待機位置の位相90コマ)。
いずれもユーザーの指摘で発覚しており、Claude Code 自身は気づいていなかった。
ユーザーの指示「すでに実装済みのところで根拠のない実装がないかの横展開調査」による。

## 判定の区分

| 区分 | 意味 |
|---|---|
| **A** | 原作の逆アセンブルに出典がある(アドレスを書ける) |
| **B** | ユーザーが決めた、または設計書で明示的に決めた |
| **C** | 実測で決めた |
| **D** | **出典なし。Claude Code が置いた** |

## 判定の土台についての注意 (先に読むこと)

`docs/reference/original-vb22-physics.md` 第7節の「原作値→本作値」の換算表は、
**その資料自身が冒頭で「第4節・第5節・第7節に誤りあり」「data/rules_original.json の
換算値は誤った前提で作られており要見直し」と警告している。**

さらに換算は次の未確認の仮定に依存する。

- フレームレート **≈30fps** (vsync 56.4Hz の2間引き = 28.2fps を丸めたもの)。**要実機確認**
- Y換算 **1.5 px/単位**、X換算 **3.11 px/単位**。いずれも仮定
- 資料自身が「フレームレート仮定が外れている場合は全速度が同率でズレる」と明記

**したがって「原作換算値と違うから誤り」という判定はできない。**
換算の物差しそのものが未検証である。

一方、**換算を経由しない数値**(回数・確率・タッチ数・分岐条件・比率)は
そのまま比較できる。監査ではこの2種を分けて扱う。

## 1.3 原作に存在しない機構を入れている (D)

**原作には無いので「原作準拠」では正当化できない。逸脱の理由が要る。**

| 実装 | 原作 | 現在の記録 |
|---|---|---|
| CPUの狙い誤差 (`P_AIM` 40/25/15/8) | **狙いにノイズを注入する箇所は一切ない** (`cpu:223`) | 理由の記録なし → **#84** |
| CPUのミス抽選 (`P_MISS` 64/13/13/8) | **わざとミスするロジックは存在しない** (`cpu:227`) | 理由の記録なし → **#84** |
| 難易度ごとの予測深度 (0/0/2/3) | 原作の `predict()` は全難易度共通で30フレーム上限 | 理由の記録なし |

# 第2部: 換算を経由するため判定できないもの

以下は原作に対応物があるが、**換算の物差し(30fps仮定・px/単位)が未検証**のため
「合っている/間違っている」を判定できない。

| 実装値 | 原作 | 資料の換算値 | 判定 |
|---|---|---|---|
| `gravity_px_s2 = 1150` | ボール +5/frame | 6900 | **判定不能**(換算が誤り警告の対象) |
| `move_speed_px_s = 180` | 歩幅 2/frame | 190 | 判定不能 |
| `bump_up_speed_px_s = 520` | 打球強さ 26〜34(キャラ別) | 記載なし | 判定不能。**なお原作はキャラ別、本作は全キャラ共通**(`controls:103`) |
| `hit_inertia_pct = 30` | レシーブ vy に25%、ブロックは持ち越し | ― | **比率は比較可能。25% vs 30%、かつ原作は vy のみ・本作は vx と vy 両方** |
| ジャンプ高さ表 `[155,145,135,120,100]` | ジャンプ初速 10〜26(キャラ別) | 1170(トメ) | 判定不能。**ただし幅は比較可能。原作2.6倍差 vs 本作1.55倍差** |
| スピードランク `[120,110,100,90,80]` | 歩幅は全キャラ2で共通、ダッシュのみ4〜5 | ― | **原作に歩行速度のキャラ差は無い。本作は独自** |

**この部で「判定不能」が並ぶのは、換算の物差しを直す(#87)まで解消しない。**
#87 は原作物理資料の誤り3件と `rules_original.json` の見直しを扱う。

# 第3部: 是正の方針

## 即座に是正できる (原作に出典がある)

1. **#66 第3段** — CPU待機位置・退避位置・前衛後衛の入替を原作の表(`0x8406`/`0x7E31`/`0x7E9D`)へ置換
2. **#66 第4段** — 近接時の打撃抑制を原作の8px(本作24px)へ、ブロック寄せをネットから8px(本作24px)へ
3. **#85** — ジャンプ発火条件を原作のAND判定(`0x8824`)へ

## 理由を書いて残すか、原作へ寄せるかの判断が要る

4. **#84** — 狙い誤差・ミス抽選。原作に存在しない機構。廃止するか、逸脱の理由を仕様書に書く
5. 難易度ごとの予測深度・配球知能。同上
6. 反応遅延の 24/16/13/12。方針は記録済みだが値の導出がない。実測で決め直すか根拠を書く

## 換算の物差しを直してから (#87)

7. 重力・移動速度・打球強さ・ジャンプ高さの各値。物差しが直るまで判定を保留する

## 新規機構として理由を明記すべきもの

8. ジャスト判定の45%、ブレーキのランク差、スピードのランク差。
   原作に対応物が無いので「原作準拠」では説明できない。設計意図を書く

# 監査の限界

- **表示層は対象外**。ゲームの挙動を決めない数値は監査していない
- **`rules.json` の74キーすべてを個別に追跡してはいない。**
  挙動への影響が大きいものと、原作に明確な対応物があるものを優先した
- **原作側の資料に「未解明」と書かれた項目は判定できない。**
  特に画面上の x/y 縮尺比(確度:低)、必殺技の対応表(確度:中)、
  地上必殺技11本の速度式(確度:中)
